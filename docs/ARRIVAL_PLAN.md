# Arrival Brief - 현대차 차량용 앱 공모전 기획·구현 현황

2026-10-30. 공개 자료와 소프트웨어 검증으로 준비한 프로토타입이다. 직접 인터뷰·실사용 효과 측정·실차 검증·주최 측 승인은 아직 없다.

## 해결할 문제

행사 안내문에는 회의실이 적혀 있어도 운전자는 어느 문으로 들어가 어느 구역에 주차할지 별도로 확인해야 한다. 코엑스 공식 안내가 세부 목적지별 진입문과 추천 구역을 구분한다는 사실을 바탕으로, 행사 안내에서 출발 전 도착 준비까지 이어지는 흐름을 설계했다.

첫 사용자는 현재 안내 가능한 코엑스 삼성동 회의실의 행사에 처음 차량으로 방문하는 운전자다. 전시장 Hall A/B/C/D는 지원하지 않는다. 코엑스 공식 안내와 카카오의 실내 주차 안내가 이미 있으므로, 차별점은 행사 안내문의 장소·층·높이·자료 상충을 검토하고 확정하는 과정에 둔다. 실제로 검색과 확인 시간을 얼마나 줄이는지는 검증할 가설이다. [공개 근거와 기존 대안 비교](USER_EVIDENCE.md)에 확인한 사실과 아직 모르는 것을 구분했다.

## 핵심 흐름

안내문 입력 또는 회의실 목록 선택 → 행사 시설 확인 → 차량 전체 높이 확인 → 안전한 주차 상태에서 브리핑 확정 → 입력 제한 시 메모리에 남아 있는 확정 내용 유지.

웹은 정차·주행·상태 미확인을 사용자가 바꾸는 시뮬레이션이다. Android는 기본 상태가 `UNKNOWN`이며 `CarUxRestrictions`에서 입력을 허용하는 값을 받을 때만 입력 화면을 연다. 이는 물리적 정차를 자동 판정한 결과가 아니다. 웹과 Android 모두 브리핑 확정에 사용자의 전체 높이 확인과 안전한 주차 상태 확인이 필요하다. Android의 시설 확인은 NaviHelper 대조 결과 또는 명시적인 수동 확인으로 구분한다.

차량 플랫폼에서는 데모 진입을 막는다. 일반 Android에서는 별도 안내에 동의한 뒤 데모를 사용할 수 있다. 제한 상태로 바뀌면 입력·복사를 잠그고 마지막 확정 브리핑을 유지한다. 실제 차량 운영체제가 앱 전체를 제한할 수 있으므로 이 화면의 실제 표시 여부는 런타임 검증이 필요하다.

COEX 외 시설, 마곡, 취소·변경 표현, 잘못된 층수와 선택 장소의 충돌은 추가 확인으로 처리한다. 숫자나 날짜만으로 목적지를 만들어내지 않는다. 자료가 바뀌면 사람이 차이를 검토한 뒤 확인일과 데이터를 갱신한다.

## 현재 구현

웹은 HTML/CSS와 Vanilla JS로 작성했고 외부 라이브러리 없이 실행한다. `engine.mjs`는 규칙에 따라 장소·검토 사유·확정 가능 여부를 반환한다. 외부 생성형 모델이 위치를 추측하는 방식은 사용하지 않으며 행사 안내 원문을 서버로 보내지 않는다. 복사와 TXT 다운로드를 지원하고 안내문을 바꾸면 이전 선택·확정을 폐기한다.

Android는 Kotlin 기반 네이티브 화면, `BriefEngine`, `BriefSession`, `PlatformVehicleGateway`를 분리했다. 행사 안내 원문과 차량 높이는 현재 세션 메모리에만 유지한다. 화면 회전에는 세션을 전달하고 프로세스 종료 후 원문을 복원하지 않는다. 최근 목적지는 사용자가 명시적으로 저장한 목적지 ID·시각·자료 버전 1건만 24시간 안에 복구·삭제할 수 있도록 구현했다. 웹은 localStorage, Android는 private preferences를 사용하고 원문·높이·내비 이름·주소·확정 브리핑은 보관하지 않는다. 복구 시 높이·시설·주차를 다시 확인하며 자동 확정하지 않는다. 만료·미래 시각·자료 버전 불일치·미지원 ID·상충 목적지는 복구하지 않는다. 주행 제한 중 프로세스 종료 후 확정 브리핑을 복원하는 기능은 없다. 구현·시험 결과는 검증 기록과 대조한다. 연결별 토큰으로 이전 차량 서비스의 지연 콜백이 잠금을 해제하지 못하게 했다.

Pleos 연동은 NaviHelper 3.0.5의 목적지 이름·주소를 이용한 시설 대조와 CarUxRestrictions의 입력 제한에 집중한다. 사용자 요청과 플랫폼의 입력 허용을 확인한 뒤 현재 내비 목적지와 행사 시설을 대조하고, 다른 시설이거나 응답을 확인할 수 없으면 그 상태를 구분한다. Vehicle·브레이크 진단 의존성과 관련 권한은 제거했다. 시설 불일치와 조회 중 상태는 확정을 막고, 미조회·판정 불가·응답 불가에는 사용자의 시설 확인을 요구한다. 이미 확인된 불일치는 실패한 재조회나 수동 체크로 지울 수 없다. 대조는 요청한 시점의 시설 확인이며 연속 목적지 감시나 회의실·진입문 검증이 아니다. 실제 SDK 응답·권한·상태 전환의 성공 여부는 런타임 검증 기록과 구분한다. 내비 목적지나 경로를 변경하지 않는다.

## 빌드·검증 상태

현행 `0.3.0-prototype`의 웹 테스트 21개와 Android JUnit 37개(엔진 17개, 세션 10개, 시설 대조 8개, 최근 목적지 2개)가 통과했다. 양쪽 엔진은 같은 50개 판단 사례를 시험하며 이를 테스트 개수에 중복해 더하지 않는다. versionCode 3 release APK의 크기는 5,067,560바이트이고 apksigner v2 검증을 통과했다. compile/target SDK는 35, minSdk는 28이다. Lint 오류·경고는 0개다. 버전·파일 해시·시험·런타임은 [검증 JSON](verification/release-verification.json)을 기준으로 한다.

일반 Android 9에서 0.3.0의 업그레이드 설치·첫 실행·명시적 데모·시설/높이/안전 주차 확인 후 확정·주행 예시 잠금·목적지 보관·프로세스 종료 후 초안 복구를 확인했다. 복구한 초안은 높이가 비어 있고 모든 확인이 해제되며 확정 버튼도 비활성 상태였다. 실제 NaviHelper 응답과 차량 UX 전환을 확인한 결과는 아니다. 소프트웨어 에뮬레이션 환경의 System UI 응답 지연·UIAutomator null root로 성능과 장시간 안정성은 평가하지 않았다.

Pleos 에뮬레이터 실행을 시도했으나 공식 환경 요구사항을 충족하지 못한 환경에서 OS 초기화와 APK 설치가 실패했다. 설치·첫 실행·서비스 응답·주행 제한 전환은 재검증이 필요하다. [런타임 기록](verification/android-runtime.md)에 관측 결과를 남겼으며 GPU 부재를 단일 실패 원인으로 단정하지 않는다. `CarUxRestrictions` 연결 코드와 상태 테스트가 있다는 사실을 실차 동작 완료로 바꾸어 쓰지 않는다. [Android 빌드 기록](ANDROID_BUILD.md)에 파일 해시, 서명, 경고와 재현 명령을 남겼다.

## 시연과 평가

1. 오디토리움 안내에서 북문·B3 블루존을 확인한다.
2. 스튜디오159 안내에서 동문·B2 퍼플존을 확인한다.
3. 여러 후보가 있는 안내는 방문 장소를 명시 선택하기 전까지 확정하지 않는다.
4. 출처가 상충하는 세 분류는 확정·저장을 막고 확인이 필요한 이유를 보여준다.
5. 높이 초과, 층 충돌, 취소·변경 문맥과 미지원 시설은 각 사유를 표시한다.
6. 브리핑 확정 후 입력 제한 상태로 바뀌면 편집을 잠그고 확정 내용만 유지한다.
7. 미확정 상태에서 주행·미확인 예시로 바뀌면 새 안내를 만들지 않는다.

평가 항목은 장소 매칭과 예외 처리, 잘못된 확정 차단, 높이 제한, 입력 제한, 출처 표시다. 단위 테스트는 정해진 입력에 대한 검사이며 실제 이용자 전체의 정확도를 뜻하지 않는다. 시간 절감·재사용률·만족도는 아직 측정하지 않았다.

두 편의 33초 영상은 최신 웹 화면 캡처와 스톡 도입을 편집해 갱신했다. 실차 촬영이나 연속 화면 녹화로 표현하지 않는다.

## 다음 검증 순서

공식 환경 요구사항을 충족하는 Pleos 환경에서 OS 부팅과 패키지 서비스 정상화를 확인한 뒤 APK 설치와 첫 실행, 플랫폼 제한 상태 변화, 서비스 연결 해제·재연결, NaviHelper의 목적지 이름·주소 응답과 시설 대조를 재검증한다. 사용자 요청이 없거나 플랫폼 입력 제한 중에는 새 조회를 시작하지 않는지도 확인한다. 검증되지 않은 좌표나 경로 전달을 기능으로 약속하지 않는다.

[공식 SDK 안내](https://document.pleos.ai/docs/pleos-only/create-my-project)에 안내된 NaviHelper를 사용한다. 도입한 SDK 이름을 늘리는 대신 확인 과정에 쓰이는 목적지 읽기에 범위를 한정한다. 아직 제공되지 않는 API를 필수 흐름에 넣지 않는다.

시설 확대는 현재 8개 분류의 예외 처리와 출처 갱신 체계를 검증한 뒤 진행한다. 공식 자료가 상충하는 세 분류의 안내 재개는 최신 운영 정보 확인이 먼저다.

## 사용자 확보와 반복 이용 가설

초기 유입 후보는 행사 안내 링크와 Pleos App Market이다. 제휴·입점·실제 노출은 확보하지 않았다. 휴대폰으로 받은 행사 안내를 차량 앱에서 어떻게 확보할지도 검증 대상이다. 웹 체험과 차량 앱 사이의 자동 전달이 완료된 것으로 설명하지 않는다.

MAU는 월 1회 이상 브리핑을 확정한 순이용자로 정의한다. 전체 전시 참가자를 모수로 삼지 않고 지원 차량·대상 회의실 행사 참여·안내 도달·설치·확정 단계를 나눠 계산한다. [조건별 산식](USER_EVIDENCE.md)의 약 2명·13명·67명은 모두 입력 근거가 없는 가상 조건의 계산 결과다. 현재 사용자 실적이나 시장 전망은 아니다.

30일 재확정률과 다음 행사 방문 기회가 있는 사람의 재사용률을 구분한다. 후자의 분모는 방문 기회에 대한 별도 관측 없이는 알 수 없다. 최근 목적지 1건의 명시적 복구는 같은 방문 준비 중 재입력 부담을 줄이는 기능이며 고객 유지율을 입증하지 않는다.

확장은 공식 출처·검토 상태·갱신 기록·계약 테스트를 통해 안내와 보류를 관리할 수 있을 때 진행한다. 운영자 배포·자료 관리 기능을 유료 후보로 검토하지만, 현재 제휴·매출·결제 의향·운영 비용 실적은 없다.

## 제출 운영과 자료

공식 양식의 익명 심사 지침과 개인 GitHub 계정이 노출되는 저장소 공유 방법은 운영 측 확인 사항이다. 비공개 저장소를 열어줄 심사용 계정도 2026-10-30 확인 범위에서는 공지되지 않았다. 계정을 임의로 정하거나 접근 확인 없이 제출 준비가 끝났다고 표시하지 않는다.

개인정보·동의서·서명·연락처는 이 저장소에 추가하지 않는다. release 서명키도 별도 보관한다. 본 문서는 접수 완료나 채용·수상 가능성을 보장하지 않는다.

딥네이비와 아이스블루, 읽기 쉬운 진입문·층 표기를 사용하며 확인되지 않은 지도를 만들지 않는다. 앱 아이콘과 UI는 독립 제작물이다. 참고 자료와 라이선스는 [ATTRIBUTIONS.md](../ATTRIBUTIONS.md)에 정리한다.
