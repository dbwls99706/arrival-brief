# Arrival Brief - 현대차 차량용 앱 공모전 기획·구현 현황

2026-10-30. 공개 자료와 소프트웨어 검증으로 준비한 프로토타입이다. 직접 인터뷰·실사용 효과 측정·실차 검증·주최 측 승인은 아직 없다.

## 해결할 문제

행사 안내문에는 회의실이 적혀 있어도 운전자는 어느 문으로 들어가 어느 구역에 주차할지 별도로 확인해야 한다. 코엑스 공식 안내가 세부 목적지별 진입문과 추천 구역을 구분한다는 사실을 바탕으로, 행사 안내에서 출발 전 도착 준비까지 이어지는 흐름을 설계했다.

첫 사용자는 전시·컨퍼런스 장소를 처음 방문하는 운전자다. 주차 추천 자체의 최초성을 주장하지 않으며, 안내문 속 장소를 확인하고 출처가 있는 브리핑을 확정하는 경험에 집중한다. 실제로 검색과 확인 시간을 얼마나 줄이는지는 검증할 가설이다.

## 핵심 흐름

안내문 입력 → 세부 목적지 확인 → 차량 전체 높이 확인 → 안전한 주차 상태에서 브리핑 확정 → 입력 제한 시 확정 내용 유지.

웹은 정차·주행·상태 미확인을 사용자가 바꾸는 시뮬레이션이다. Android는 기본 상태가 `UNKNOWN`이며 `CarUxRestrictions`에서 입력을 허용하는 값을 받을 때만 입력 화면을 연다. 이는 물리적 정차를 자동 판정한 결과가 아니다. Android의 브리핑 확정에는 사용자의 전체 높이 확인과 안전한 주차 상태 확인이 모두 필요하다.

차량 플랫폼에서는 데모 진입을 막는다. 일반 Android에서는 별도 안내에 동의한 뒤 데모를 사용할 수 있다. 제한 상태로 바뀌면 입력·복사를 잠그고 마지막 확정 브리핑을 유지한다. 실제 차량 운영체제가 앱 전체를 제한할 수 있으므로 이 화면의 실제 표시 여부는 런타임 검증이 필요하다.

8개 분류 중 5개를 안내하고 3개는 확인을 보류한다. '코엑스 모든 회의실 지원'이나 '8개 분류 모두 안내 가능'으로 표시하지 않는다. 아셈볼룸 분류가 있다는 이유만으로 201~211호 번호를 모두 자동 해석한다고 주장하지 않는다.

차량 전체 높이가 지하 진입 제한 2.2m를 넘으면 동선 사용을 막는다. 같은 높이면 여유가 있다는 보증 없이 현장 표지와 적재물 확인 경고를 표시한다. 하역 동선을 승객 하차나 승용차 경로로 사용하지 않는다. 실시간 빈자리·혼잡도·진입 가능성·입구 좌표·실내 경로는 제공하지 않는다.

COEX 외 시설, 마곡, 취소·변경 표현, 잘못된 층수와 선택 장소의 충돌은 추가 확인으로 처리한다. 숫자나 날짜만으로 목적지를 만들어내지 않는다. 자료가 바뀌면 사람이 차이를 검토한 뒤 확인일과 데이터를 갱신한다.

## 현재 구현

웹은 HTML/CSS와 Vanilla JS로 작성했고 외부 라이브러리 없이 실행한다. `engine.mjs`는 규칙에 따라 장소·검토 사유·확정 가능 여부를 반환한다. 외부 생성형 모델이 위치를 추측하는 방식은 사용하지 않으며 행사 안내 원문을 서버로 보내지 않는다. 복사와 TXT 다운로드를 지원하고 안내문을 바꾸면 이전 선택·확정을 폐기한다.

Android는 Kotlin 기반 네이티브 화면, `BriefEngine`, `BriefSession`, `PlatformVehicleGateway`를 분리했다. 입력은 현재 세션 메모리에만 유지한다. 화면 회전에는 세션을 전달하고 프로세스 종료 후 원문을 복원하지 않는다. 연결별 토큰으로 이전 차량 서비스의 지연 콜백이 잠금을 해제하지 못하게 했다.

Pleos Vehicle 2.3.2와 NaviHelper 3.0.5의 읽기 진단 코드를 포함한다. 초기화, 브레이크 페달 속성 접근 가능 여부, 내비 목적지 정보 응답을 확인하며 실패·시간 초과를 표시한다. 입력 허용 판단은 별도 플랫폼 UX 제한 신호로 처리한다. 브레이크 값만으로 정차를 판단하거나 내비 목적지를 전달하지 않는다.

## 빌드·검증 상태

2026-10-30에 웹 테스트 14개와 Android JUnit 23개(엔진 13개, 세션·상태 10개)가 통과했다. `0.2.0-prototype` release APK를 생성했고 apksigner v2 검증도 통과했다. compile/target SDK는 35, minSdk는 28이다. Lint 결과는 오류 0개, 경고 4개다.

Pleos 에뮬레이터 실행을 시도했으나 공식 환경 요구사항을 충족하지 못한 환경에서 OS 초기화와 APK 설치가 실패했다. 설치·첫 실행·서비스 응답·주행 제한 전환은 재검증이 필요하다. [런타임 기록](verification/android-runtime.md)에 관측 결과를 남겼으며 GPU 부재를 단일 실패 원인으로 단정하지 않는다. `CarUxRestrictions` 연결 코드와 상태 테스트가 있다는 사실을 실차 동작 완료로 바꾸어 쓰지 않는다. [Android 빌드 기록](ANDROID_BUILD.md)에 파일 해시, 서명, 경고와 재현 명령을 남겼다.

## 시연과 평가

1. 오디토리움 안내에서 북문·B3 블루존을 확인한다.
2. 스튜디오159 안내에서 동문·B2 퍼플존을 확인한다.
3. 여러 후보가 있는 안내는 방문 장소를 명시 선택하기 전까지 확정하지 않는다.
4. 출처가 상충하는 세 분류는 확정·저장을 막고 확인이 필요한 이유를 보여준다.
5. 높이 초과, 층 충돌, 취소·변경 문맥과 미지원 시설은 각 사유를 표시한다.
6. 브리핑 확정 후 입력 제한 상태로 바뀌면 편집을 잠그고 확정 내용만 유지한다.
7. 미확정 상태에서 주행·미확인 예시로 바뀌면 새 안내를 만들지 않는다.

평가 항목은 장소 매칭과 예외 처리, 잘못된 확정 차단, 높이 제한, 입력 제한, 출처 표시다. 단위 테스트는 정해진 입력에 대한 검사이며 실제 이용자 전체의 정확도를 뜻하지 않는다. 시간 절감·재사용률·만족도는 아직 측정하지 않았다.

두 편의 33초 영상은 최신 웹 화면 캡처와 스톡 도입을 편집해 갱신했다. 실차 촬영이나 연속 화면 녹화로 표현하지 않는다.

## 다음 검증 순서

공식 환경 요구사항을 충족하는 Pleos 환경에서 OS 부팅과 패키지 서비스 정상화를 확인한 뒤 APK 설치와 첫 실행, 플랫폼 제한 상태 변화, 서비스 연결 해제·재연결, 읽기 진단을 재검증한다. 필요하면 정차 중 내비 목적지와 행사 시설을 대조하는 기능을 검토하되 반환 정보와 권한부터 확인한다. 검증되지 않은 좌표나 경로 전달을 기능으로 약속하지 않는다.

[공식 SDK 안내](https://document.pleos.ai/docs/pleos-only/create-my-project)는 Vehicle State와 NaviHelper를 사용 가능 상태로, FusedLocation·TTS·STT·Vehicle Control은 준비 중으로 안내한다. 아직 제공되지 않는 API를 필수 흐름에 넣지 않는다.

시설 확대는 현재 8개 분류의 예외 처리와 출처 갱신 체계를 검증한 뒤 진행한다. 공식 자료가 상충하는 세 분류의 안내 재개는 최신 운영 정보 확인이 먼저다.

개인정보·동의서·서명·연락처는 이 저장소에 추가하지 않는다. release 서명키도 별도 보관한다. 본 문서는 접수 완료나 채용·수상 가능성을 보장하지 않는다.

딥네이비와 아이스블루, 읽기 쉬운 진입문·층 표기를 사용하며 확인되지 않은 지도를 만들지 않는다. 앱 아이콘과 UI는 독립 제작물이다. 참고 자료와 라이선스는 [ATTRIBUTIONS.md](../ATTRIBUTIONS.md)에 정리한다.
