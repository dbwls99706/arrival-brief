# Arrival Brief - 현대차 차량용 앱 공모전 기획·구현 현황

2026-10-28. 직접 인터뷰 없이 공개 근거로 설계한 준비용 프로토타입. 사용자 검증·실차 검증·주최측 승인을 받은 결과물이 아니다.

## 문제와 차별점

큰 시설 이름을 내비에 넣어도 행사 티켓의 세부 회의실에 적합한 입구·주차 구역을 다시 찾아야 한다는 가설을 검증한다. 코엑스 공식 운영 자료가 세부 목적지별 진입문과 주차 구역을 구분한다는 것은 확인된 사실이다. 카카오모빌리티가 이미 코엑스 실내 내비게이션을 제공하므로 주차 추천 자체를 신규 기능으로 주장하지 않는다. 차별점은 비정형 행사 안내를 세부 목적지로 해석하고 검증된 출처로 브리핑을 만들며 주행 상태에 맞게 정보를 축소하는 연결 경험이다.

## 사용자와 핵심 흐름

초행 전시·컨퍼런스 방문 운전자. 안내문 붙여넣기 → 세부 목적지 확인 → 차량 전체 높이 확인 → 출발 전 브리핑 확정 → 주행 시 확정 내용만 보기. 모든 상세 입력·선택·복사·다운로드는 정차 모드에서만 활성화한다. 상태 미확인도 잠근다. 웹 모드는 명시적으로 시뮬레이션이다.

## 데이터

공식 원문: https://business.coex.co.kr/guide/conference-room-parking-information/general-vehicle/
확인일: 2026-10-28. 코엑스 삼성동 8개 목적지 범위. 오디토리움·그랜드볼룸·아셈볼룸은 북문/B3블루존, 스튜디오159·컨퍼런스룸E는 동문/B2퍼플존, 300~328·400~403회의실은 동문/B2그린존, THE PLATZ는 동문/B2. 공통 지하 진입 높이 제한 2.2m. 현장 안내 우선.

하역 동선은 승객 하차 동선으로 사용하지 않는다. 실시간 빈자리·혼잡도·진입 가능성·입구 좌표·정확한 실내 보행 경로는 제공하지 않는다. COEX 외 시설, 서로 다른 시설, 변경/부정 문맥, 층 정보 불일치는 확인 요청으로 처리한다. 룸 301 같은 세부 회의실 번호만 해석하며 임의 숫자나 날짜에서 목적지를 추측하지 않는다.

## 구현

Vanilla JS HTML/CSS, 외부 라이브러리 의존성 없음. `engine.mjs`는 pure functions로 근거·상태를 반환한다. 엔진은 설명 가능한 규칙 기반이며 LLM 호출로 위장하지 않는다. 사용자 텍스트는 innerHTML 삽입 전 이스케이프하고 외부 서버로 전송하지 않는다. 브리핑은 TXT 다운로드·클립보드 복사. 화면 변경 시 확정 상태를 폐기한다.

Android native Kotlin 앱 소스가 `android/`에 있다. 동일 정책, 실제 모드는 미연결 UNKNOWN으로 fail closed. 실제 Pleos Vehicle2.3.2/NaviHelper3.0.5 읽기 전용 진단을 구현했다. 서비스 초기화, 브레이크 페달 capability와 값 조회, 내비 목적지 조회 이벤트를 실제 API로 호출하며 실패·타임아웃을 표시한다. 브레이크 페달 값으로 주차 상태를 추정하지 않으며 실제 모드 입력은 UNKNOWN 잠금을 유지한다. APK 빌드 및 서비스 런타임 상태는 빌드 기록을 따로 확인한다. SDK 소개만으로 권한·사용 가능성을 가정하지 않는다.

## SDK와 제출 경계

https://document.pleos.ai/docs/pleos-only/create-my-project 에서 Vehicle State/NaviHelper가 사용 가능, FusedLocation/TTS/STT/Vehicle Control은 준비 중으로 확인했다. 완성 출품까지는 State+CarUxRestrictions 실제 연동, 좌표 검증 후 NaviHelper 전달, 에뮬레이터/차량 시연 검증, 참가자 release 서명이 필요하다. 현재 웹 시뮬레이터를 실차 앱이나 공모전 승인품이라고 표시하지 않는다.

## 시연과 평가

1. 코엑스 오디토리움 안내 입력 → 북문/B3블루존.
2. 컨퍼런스룸E 안내 입력 → 동문/B2퍼플존.
3. 두 장소가 든 안내 → 명시 선택까지 확정 금지.
4. 높이2.3m → 진입 제외.
5. 잘못된 시설·부정/변경 문맥·층 충돌 → 확인 요청.
6. 정차 확정 후 주행 → 입력 숨김, 확정된 브리핑 유지.
7. 미확정으로 주행 → 안내를 생성하지 않음.

평가할 지표는 기준 장소 추출 정확도, 모호/미지원 입력의 잘못된 자동확정률, 높이 초과 차단률, 비정차 상태 입력 허용률, 출처 포함률이다. 사용자의 실제 시간 절감·재사용률·만족도는 아직 측정하지 않았다. 초기 8개 목적지 테스트 성능을 일반 시설 전체 성능으로 주장하지 않는다.

## 디자인과 근거

Anthropic 공개 frontend-design 가이드, GOV.UK 확인 화면·Carbon 데이터 표 원칙과 Pleos 주의분산 설계 원칙에 근거. 딥네이비/아이스블루, 큰 진입문·층 숫자, 가짜 지도 없이 텍스트 브리핑. 외부 자료와 라이선스는 `../ATTRIBUTIONS.md`와 `HYUNDAI_FOCUS.md` 참조.

## 검토 반영

제품/UX 검토에서 '코엑스가 아닌 킨텍스', '코엑스 회의실301호는 취소, 목적지는 벡스코', '오디토리움2층'의 잘못된 추출을 발견했다. 불일치 failclosed 규칙과 회귀테스트를 추가했다. 기본1.65m는 예시값이라고 필드 도움말에 표시했다. 인간 심사위원 점수와 당선 확률을 보장하지 않는다.

## 두 번째 기술 검토 반영

SDK 시뮬레이터만 존재한다는 지적에 따라 공식 Maven의 Vehicle2.3.2/NaviHelper3.0.5 AAR과 문서 API를 교차 확인하고 읽기 진단 어댑터를 추가했다. native 의사결정엔진에 8개 JUnit 테스트(8개 장소 매핑 포함)를 추가했다. 실제 차량 OS 주행규제와 좌표 검증이 남아 있어 출품완료/실차검증 완료로 표시하지 않는다.
