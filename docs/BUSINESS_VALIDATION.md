# 사업성 검증 설계와 운영 시나리오

작성·공식 기준 확인: 2026-11-02. **이 문서는 검증 전 가정과 준비한 운영 도구다. 실제 고객·배포 계약·매출·이용 성과 또는 확정 MAU 예측이 아니다.** 현재 원격 계측이 없으므로 관측 이용자 수를 보고할 수 없다. 이를 이용자 0명이라는 뜻으로 해석하지 않는다.

[공식 심사 기준](https://appdevchallenge.auto-hmg.io/guide/judging-awards)은 타깃 고객, 사용자 확보, 지속 이용·확대 가능성을 사업성 항목으로 다룬다. Pleos App Market 지원도 별도 검증·심사 및 차종·지역 조건을 거치며 배포를 보장하지 않는다. 아래에서는 그 조건이 충족되었다고 가정하지 않는다.

## 누구의 어떤 일을 줄일 것인가

| 대상 | 현재 다루는 일 | 검증할 가치 | 지금 제공하는 자료 |
| --- | --- | --- | --- |
| 지원 코엑스 회의실을 처음 차량으로 방문하는 참가자 | 행사 안내와 시설·차량 높이를 대조하고 주차 위치를 다시 확인 | 잘못된 확정 감소, 같은 방문의 기록 재확인 | 앱의 출발 전 확인·수동 주차 메모 |
| 반복 행사 운영자·참가 안내 담당자 | 장소·층·주차 출처를 확인해 안내문 작성, 변경 시 재배포 | 검토·수정 시간과 반복 문의 부담 감소 | [안내문 템플릿](../examples/organizer/participant-notice-template.md), [검토표](../examples/organizer/review-checklist.md) |
| 시설 자료 검토 담당자 | 원문 상충과 갱신 이력 관리 | 검토 책임·갱신 범위·보류 사유를 추적 가능하게 유지 | [확대 승인 기준](../examples/organizer/expansion-gates.md), 현재 5개 안내·3개 보류 재현 예시 |

운영자가 검토한 안내문이 참가자의 출발 준비로 이어지는 것이 유입 가설이다. 내비 경로·실시간 주차장 정보를 대체하거나 행사장의 공식 운영을 보증하지 않는다. 비용 절감과 문의 감소는 아직 측정하지 않았다. 실제로 판매할 기능·가격은 반복 운영 비용과 구매 의사를 확인한 뒤 정한다.

**첫 사업 검증의 범위는 다음 네 가지 가설로 좁힌다.** 계약·지불 의사 또는 판매 중인 상품을 뜻하지 않는다.

| 항목 | 검증할 가설 |
| --- | --- |
| 첫 구매 주체 | 반복 행사의 참가 안내를 담당하는 운영자 |
| 제공 단위 | 행사별 안내 작성·출처 검토·변경 재배포 도구. 현재는 템플릿·검토표로 준비한 단계 |
| 참가자 이용 | 운영자가 검토한 안내를 무료로 받아 출발 준비에 사용 |
| 가격 | 미정. 행사별 작성·검토·수정 비용과 운영자의 구매 의사를 확인한 뒤 결정 |

## 실제 배포 경로부터 검증한다

| 경로 | 현재 가능한 범위 | 차량 앱 유입으로 인정할 조건 |
| --- | --- | --- |
| 운영자의 기존 참가 안내 채널 → 웹 링크 또는 UTF-8 `.txt` | 운영자가 채널을 보유하고 게시를 승인한 경우에만 전달 가능. 웹은 파일·붙여넣기 체험 | 웹 이용으로만 기록한다. 공개 저장소 링크나 APK 다운로드만으로 차량 설치를 인정하지 않는다. |
| 같은 Android 기기의 텍스트 공유 → Arrival Brief | 같은 기기에 원문·공유 가능한 앱·Arrival Brief가 있어야 함 | 대상 차량 기기에서도 그 조건과 입력 허용 상태가 실제 확인되어야 함. 휴대폰의 공유 메뉴를 차량 전달로 계산하지 않는다. |
| 지원 차량에 정식 앱 배포 | 호환 차종·지역, 설치·업데이트·삭제와 차량 API 동작 검증 필요 | 승인된 배포 경로와 기기 내 원문 전달 방법을 확보한 경우만 차량 도달로 계산한다. 마켓 입점은 미확정이다. |
| 일반 Android 개발·심사용 APK | 개발 검토와 기능 재현에 사용 | Pleos 차량 배포 또는 일반 고객 확보 성과로 계산하지 않는다. |

휴대폰 → 차량 자동 전송은 구현하지 않았다. 지원 기기 설치가 가능해도 안내문을 그 기기에 가져올 수 없다면 해당 참가자의 차량 유입 경로는 닫힌다. 배포·동작 검증을 통과하지 않은 차량에 설치를 유도하는 캠페인은 진행하지 않는다. 지금 준비할 수 있는 것은 운영 문안·검토 절차·합성 예시와 계산 구조다.

## MAU 정의와 가정 계산

**MAU는 월 1회 이상 방문 준비를 확정하거나 저장한 주차 메모를 앱에서 다시 확인한 순이용자다.** 설치·실행·안내문 열람·외부 메모 앱의 QR 복사본 조회는 이 정의에 포함하지 않는다. 웹과 Android는 채널별로 먼저 집계하며 같은 사람을 중복 제거할 근거 없이는 합산하지 않는다. 이는 [사용자 근거 문서](USER_EVIDENCE.md)의 정의와 같다.

아래는 **운영자 안내를 받은 월간 코호트에서 발생할 차량 MAU의 가정 계산**이다. 제품 전체 MAU의 예측이나 시장 규모가 아니다. 안내를 받지 않고 유입된 이용자와 기존 이용자를 별도 숫자로 더하지 않는다. 전체 MAU는 확인된 활성 이용자 집합의 합집합으로 산출해야 한다.

`M = E × P × U × D × C × R × S × A`

| 변수 | 분모·의미 | 확인 방법 |
| --- | --- | --- |
| E, P | 월 지원 행사 수, 행사당 안내 대상 참가 인원. `E×P`는 중복 포함 참가 건수 | 실제 배포 권한을 확보한 행사별 인원. 전체 코엑스 행사 수로 대체하지 않음 |
| U | 중복 포함 참가 건수 대비 월 순참가자 수 | 동의한 코호트의 월중 중복 제거. 현재는 미측정 가정 |
| D | 월 순참가자 중 적어도 한 지원 행사에 직접 운전해 방문하는 비율 | 방문 교통수단 확인. 동승자는 이 운전자 코호트에 넣지 않음 |
| C | 차량 방문자 중 지원 차종·지역·플랫폼과 실제 설치 조건을 충족한 비율 | 확인된 호환성 목록과 설치 결과. Android 휴대폰 보유율로 대체하지 않음 |
| R | 위 호환 이용자 중 앱 배포와 원문 전달이 모두 실제 가능한 비율 | 같은 차량 기기에서 설치와 안내문 가져오기를 끝까지 재현 |
| S | 도달 가능한 이용자 중 앱 과업을 시작한 비율 | 최소 계측 또는 동의한 관찰. 안내 링크 클릭과 구분 |
| A | 시작한 이용자 중 월내 위 MAU 정의의 행동을 한 비율 | 올바른 확인 또는 유효 메모 재열람. 잘못된 확정은 성과에서 제외·별도 보고 |

각 비율은 바로 앞 단계에 대한 조건부 비율이다. 동질적인 코호트라는 단순화이며 행사·차종별 편차를 설명하지 못한다. 실제 측정에서는 단계별 고유 사람 집합을 세고, 평균 비율의 곱을 실측값으로 대신하지 않는다.

**아래 모든 수는 계산 설명을 위한 임의 가정이다. 관측값·목표 약속·매출 전망이 아니다.** 월 4개 행사 × 250명 = 1,000 참가 건수, U 80% → 800 순참가자, D 40% → 320 차량 방문자, S 50%를 동일하게 둔다.

| 가정 시나리오 | C 호환성 | R 설치·원문 도달 | A 유효 활성 | 산식 결과(기대값) | 표시값 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 경로 미확보를 가정 | 10% | 0% | 60% | 0 | 0명 |
| 좁은 배포 범위를 가정 | 5% | 25% | 60% | 1.2 | 약 1명 |
| 비교 기준 가정 | 10% | 50% | 60% | 4.8 | 약 5명 |
| 조건 개선을 가정 | 20% | 75% | 75% | 18 | 약 18명 |

표의 0은 **R=0이라는 가정의 계산 결과**이며 현재 실제 사용자 수가 0이라는 보고가 아니다. 소수는 기대값이고 실제 사람 수가 아니다. 중간 단계를 반올림하지 않고 표시값에서만 반올림했다.

비교 기준의 다른 가정을 고정하면 C가 5%/10%/20%일 때 M은 2.4/4.8/9.6, R이 0%/25%/50%/100%일 때 0/2.4/4.8/9.6이다. S만 50%에서 100%로 올려도 9.6이다. C 또는 R이 0이면 행사 수를 늘려도 이 경로의 결과는 0이다. 따라서 초기 우선순위는 광고량보다 **호환성 확인과 차량 기기 안의 전달 경로 실증**이다.

E가 늘어도 같은 사람들이 반복 참가하면 U가 낮아질 수 있다. 행사 2배를 MAU 2배로 간주하지 않는다. 행사 내 세션 수나 안내 재발송 횟수도 새 행사·새 사람으로 세지 않는다.

## 검증 게이트와 다음 결정

아래는 제안하는 내부 승인 기준이다. 공식 인증 기준이나 수행 완료 기록이 아니다. 사용자 인터뷰·배포·현장 관찰은 아직 실시하지 않았다.

| 단계 | 확보할 증거 | 통과 후 가능한 결정 | 보류 조건 |
| --- | --- | --- | --- |
| G0 자료 준비 | 현재 안내 5개·보류 3개 예시의 판정 일치, 출처·검토일·제약 원문 보존, 수정 공지 시나리오 | 내부 운영 리허설에 사용 | 원문 제약을 지워야 통과하거나 미지원 장소를 대체 선택하는 경우 |
| G1 차량 전달 | 지원 환경에서 설치, NaviHelper 응답, UX 제한·복귀, 같은 기기 원문 전달, 수동 QR을 주장할 경우 실제 폰 판독 | 조건을 명시한 소규모 차량 과업 검증 설계 | 앱 설치/원문 경로 불명 또는 차량 제한 우회 필요 |
| G2 운영자 실행 가능성 | 동의한 담당자가 실제 행사 안내를 작성·검토·수정하는 과정과 소요 시간, 배포·회수 담당 및 채널 | 한 행사 단위의 제한된 검증 범위 결정 | 자료 갱신 책임·수정 재전달 경로 미확보 |
| G3 이용 가치 | 사전에 정한 과업·표본·성공 기준으로 기존 안내 대비 완료율·잘못된 확정·문의·시간 측정 | 같은 지원 범위에서 후속 검증 여부 결정 | 안전상 잘못된 확정 1건이라도 나오면 원인 해결·재시험 전 확대 중단 |
| G4 반복 운영·사업성 | 다른 날짜의 지원 행사에서도 재현, 실제 기회가 있었던 사람의 재사용, 작성·검토·수정 비용, 구매 주체·의사 확인 | 가격·유료 기능 실험 및 새 시설 검토 | 효과가 관측되지 않거나 지원 비용·상충 검토량이 감당 범위를 넘음 |

G3에서 작은 표본의 오류 0건은 안전성 보증이 아니다. 전환율 목표를 맞추려고 보류 안내를 제외하지 않는다. 지원 대상, 정상 안내, 보류 안내, 도움 필요·실패를 모두 분모와 함께 보고한다. 실제 실험 전에 담당자·표본·관찰 기간·통과 기준을 고정하고 결과를 본 뒤 바꾸지 않는다.

## 측정할 것과 세지 않을 것

| 지표 | 분자 / 분모 또는 단위 | 해석 제한 |
| --- | --- | --- |
| 안내 작성·검토 부담 | 초안 작성, 출처 확인, 수정, 재배포 각각의 활동 시간(분/행사) | 대기 시간·초기 학습 시간을 별도 기록. 소프트웨어 테스트 시간이 아님 |
| 반복 문의 | 장소·층·주차 문의 건수 / 전달 확인된 안내 수 × 100 | 질문 분류·행사 규모·장소·변경 유무를 함께 비교. 인과 효과 단정 금지 |
| 입력 완료율 | 외부 도움 없이 장소 확인 단계에 도달한 사람 / 지원 안내를 받은 과업 참여자 | 확정률과 구분. 보류가 정답인 입력은 올바른 보류로 별도 측정 |
| 잘못된 확정 | 원문과 다른 장소·시설 또는 높이 초과 상태의 확정 건수 / 전체 관찰 과업 | 한 건도 숨기지 않음. 자동시험·합성 예시는 사용자 관찰 분모에 넣지 않음 |
| 수동 가져가기 완료율 | QR 내용을 폰에서 읽고 별도 저장한 사람 / 가져가기 과업을 시도한 사람 | 픽셀 디코드와 구분. 카메라·밝기·거리·실패 유형 기록 |
| 같은 방문 메모 재열람률 | 저장 후 같은 방문에 앱에서 다시 확인한 사람 / 메모 저장자 | 외부 QR 복사본 조회는 별도 과업. 고객 유지율로 부르지 않음 |
| 30일 앱 재사용률 | 첫 유효 활성 후 1~30일에 다시 유효 활성한 사람 / 30일 관찰 가능한 첫 활성 코호트 | 같은 방문의 다음날 메모 재열람도 포함할 수 있음. 새 방문의 재사용과 구분하는 시간 기준 지표 |
| 방문 기회 기준 재사용률 | 두 번째 지원 행사에서 다시 사용한 사람 / 관찰 기간 중 그 방문 기회가 확인된 사람 | 30일 재사용률과 분모가 다름. 기회 미확인을 방문 없음으로 처리하지 않음 |
| MAU | 월내 정의에 해당하는 고유 사람 수 | 동일 행사 반복 실행·웹/Android 중복·외부 복사본 조회 제외 |

현재 앱에는 원격 행동 분석이 없다. 동의한 검증에서는 무작위 연구 ID, 행사 ID, 채널, 단계 성공 여부, 필요한 시간·오류 유형만 우선 기록하고 중복 제거가 불가능하면 ‘관찰 기기/세션 수’로 보고한다. 행사 원문·주차 메모·계정·차량 번호는 지표를 위해 수집하지 않는다. 연구 ID를 실제 사람과 연결하는 방식, 보관 기한, 삭제 방법은 검증 시작 전에 별도로 정한다. 지금 수집을 시작하거나 기존 참가자 명부를 가져오는 계획은 실행하지 않는다.

## 다음 산출물

현재 실행 가능한 결과는 [운영자 자료 묶음](../examples/organizer/README.md)과 합성 예시의 기계 검증이다. 운영 절차가 준비됐다는 증거로 사용하며, 실제 운영자의 채택·시간 절감·유료 구매의 증거로 바꾸어 표현하지 않는다. [확대 승인표](../examples/organizer/expansion-gates.md)의 자료·안전·배포·운영 조건을 충족한 범위부터 검증한다.

후속 과업의 비교 조건·환경 게이트·빈 관찰란은 [이용자·운영자 검증 기록표](../examples/organizer/field-validation.md)에 준비했다.
