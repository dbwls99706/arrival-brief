# Arrival Brief 검증 기록과 남은 범위

정리일: 2026-10-29. 기존 개발 과정의 Arrival Brief 관련 실행 결과와 수정 기록을 분리해 정리했다. 아래 전체 검사를 이번 페이지 분리 작업에서 다시 실행했다는 뜻은 아니다. 공식 대회 심사나 실제 고객 평가와 구분한다.

## 2026-10-29 · 영상 배치 조정

두 영상에 약한 반대 기울기와 70px 높이 차이를 적용했다. Arrival Brief 데스크톱 화면에서 두 영상의 배치를 확인했다. 390px 프레임에서는 회전을 해제하고 두 번째 카드만 24px 낮췄다. Arrival Brief의 실제 본문 375px에서 가로 넘침이 없고, 두 번째 선택 버튼의 스크롤·선택 상태가 일치했다. 영상 파일과 재생 로직은 수정하지 않았다. 화면 증거: `docs/verification/arrival-staggered.jpg`.

## 2026-10-29 · 두 편 구성 브라우저 확인

- 데스크톱에서 같은 크기의 두 영상 카드와 33초 메타데이터, 기본 재생 컨트롤을 확인했다.
- 두 영상을 각각 Space 키로 재생하고, 두 번째 재생 시 첫 번째가 일시정지되는 것을 관측했다.
- 390px 프레임의 실제 본문 폭 375px에서 페이지 가로 넘침이 없었다. 두 번째 선택 버튼과 키보드 전환으로 선택 상태·가로 스크롤이 함께 바뀌었다.
- 별도 에이전트의 정적 검토 후 자막 다운로드 링크의 데스크톱 간격을 보완했다.
- 화면 증거: `docs/verification/arrival-two-videos.jpg`. 실제 모바일 기기나 모든 브라우저의 검증을 의미하지 않는다.

## 2026-10-29 · 두 번째 시연 영상의 화면 확인

Arrival Brief 전용 소개에 ‘도착 준비’와 ‘목적지 확인’ 영상 두 편을 구성했다. 두 번째 영상은 `arrival/?example=ambiguous`의 복수 장소 예시를 브라우저에서 실행한 화면 캡처 편집이다.

- 오디토리움과 컨퍼런스룸 E가 함께 있는 안내문에서 방문 장소 선택을 요청하는 상태를 확인했다.
- 사용자가 컨퍼런스룸 E · 3F를 선택하고 확정한 뒤 동문·B2 퍼플존 브리핑이 표시되는 것을 확인했다.
- ‘주행’ 버튼의 `aria-pressed=true` 상태와 앞서 확정한 컨퍼런스룸 E 브리핑이 유지되는 화면을 확인했다.
- 주행 화면에는 ‘출발 전에 확정한 브리핑입니다’라는 표시와 실제 차량 미연결 안내가 남는다.

추가 영상의 33.000초·720×1280·24fps·H.264/yuv420p·오디오 없는 단일 스트림을 확인했고, FFmpeg 전체 디코딩에서 오류가 없었다. 한국어 WebVTT 6구간은 0초부터 33초까지 이어진다. 기존 첫 번째 MP4의 SHA-256은 변경되지 않았다.

제작 중 사용한 캡처 원본은 이 저장소에 포함하지 않는다. 실시간 화면 녹화, 실제 운전 영상이나 Pleos 실차 연동 검증이 아니다. 최초 높이 1.65m는 시연 값이다.

웹 시험 12개와 Kotlin 시험 8개는 서로 다른 범위다. 다른 제품·공통 서버를 포함한 전체 시험 수를 Arrival Brief 단독 결과로 표시하지 않는다. mock 제공자 테스트나 빌드 성공을 실제 LLM 품질·차량 연결 검증으로 세지 않는다.

## 독립 검토에서 반영한 수정

- ‘코엑스가 아닌 킨텍스’와 취소·변경 문맥을 지원 목적지로 잘못 확정하던 경로를 차단했다.
- 오디토리움의 층이 일치하지 않으면 확인 요청으로 처리한다.
- 초기 차량 높이 1.65m를 실제 차량 값으로 오인하지 않도록 예시값임을 표시한다.
- 사용자의 목적지 선택과 안내 입력이 달라지면 이전 확정 결과를 폐기한다.
- 정차 예시를 선택하면 안내 입력 위치로 이동하고, 브리핑 확정 후 결과 제목으로 초점을 옮긴다.
- 영상 재생은 브라우저 기본 컨트롤을 사용한다. 자동 재생과 별도 원형 재생 오버레이를 추가하지 않는다.

검토자는 별도 에이전트이며 주최 측 심사위원이 아니다. 인터뷰, 실제 방문 시간 절감 및 운전 중 사용성 평가는 수행하지 않았다.

## 아직 확인하지 않은 것

1. Pleos 기기·에뮬레이터의 실제 서비스 초기화와 SDK 응답, 차량 권한 승인.
2. 실제 차량 상태와 `CarUxRestrictions`의 연결 및 운전 중 UI 제한 검증.
3. 진입구 좌표, 실시간 주차 빈자리, 실내 경로와 실제 내비 목적지 전달.
4. 참가자 release 서명, 최종 제출 패키지와 접수 완료.
5. 실제 사용자 만족도·시간 절감과 일반 시설 전체로의 해석 정확도.

`ANDROID_BUILD.md`에 빌드 환경·파일 해시·명령과 원본 증거 경로를 기록했다. 다운로드 APK는 테스트용이라는 상태를 유지한다.
