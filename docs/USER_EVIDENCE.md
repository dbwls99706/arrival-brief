# 사용자 문제와 사업 가설의 근거

확인일: 2026-10-30. 공개 원문, 구현한 범위, 아직 검증하지 않은 사업 가설을 구분한다. 직접 인터뷰, 고객 관찰, 제휴 계약과 사용자 성과 데이터는 없다.

## 초기 대상

현재 안내 가능한 코엑스 삼성동 회의실의 행사에 처음 차량으로 방문하는 운전자다. 오디토리움·그랜드볼룸·아셈볼룸·스튜디오159·THE PLATZ가 안내 범위이고, 컨퍼런스룸 E·300~328호·400~403호는 출처 상충으로 확정을 보류한다. 전시장 Hall A/B/C/D와 다른 시설은 현재 대상에 포함하지 않는다.

이 범위는 시장 규모를 뜻하지 않는다. 실제 행사 참가자 중 지원 차량을 이용하고, 앱을 설치할 수 있으며, 도착 안내가 필요한 사람이 얼마나 되는지는 조사되지 않았다.

## 기존 대안과 비교

| 관점 | 코엑스 공식 안내 | 카카오 공식 소개에서 확인한 기능 | Arrival Brief의 범위 |

| 실시간·실내 길안내 | 이 비교의 대상 페이지 범위 밖 | 공식 서비스 소개에 있음 | 제공하지 않음 |
| 자료 상충 처리 | 원문 확인 | 인용한 자료에서 확인하지 않음 | 상충 원문을 나란히 제시하고 확정 보류 |

차별화의 초점은 **행사 안내를 출발 전 검토 가능한 브리핑으로 바꾸고, 실제 주차 위치 기록을 같은 방문의 귀가 때 다시 확인하는 과정**이다. 주차 안내 자체의 최초성이나 기존 내비보다 우수한 경로를 주장하지 않는다. 차량 화면의 이점은 플랫폼의 입력 제한과 연결하고, 내비 목적지와 행사 시설이 맞는지 확인하는 흐름으로 검증해야 한다. Pleos SDK 실기 응답 성공은 별도 확인 대상이다.

## 유입과 재사용을 연결하는 제품 가설

단순 주차 정보 조회만으로는 방문자가 다시 앱을 열 이유가 약하다. 검증 후보의 가설은 **받은 행사 안내를 준비에 쓰고, 실제 주차 위치를 남겨 같은 방문의 귀가 때 다시 여는 것**이다. 공식 추천 주차와 실제 주차 기록을 구분한다. 추천 구역에 실제로 주차했다는 가정이나 차량 위치 자동 추적은 사용하지 않는다.

| 단계 | 구현 또는 준비 범위 | 검증할 질문 |
| --- | --- | --- |
| 받은 안내로 시작 | 같은 Android 기기에서 텍스트 공유수신, 웹 텍스트 파일/붙여넣기 | 안내문을 다시 타이핑하지 않고 지원 행사장을 확인할 수 있는가? |
| 출발 전 준비 | 시설·차량 전체 높이·안전 주차 확인, 공식 자료 상충 보류 | 기존 내비·공식 주차표만 보는 흐름보다 확인 실수가 줄어드는가? |
| 현장에 주차 | 실제로 주차한 층·구역·기둥을 64자 이내로 직접 저장 | 추천 구역과 다른 곳에 세운 경우에도 기록을 남기는가? |
| 기록을 가지고 내리기 | Android에 저장한 메모를 명시적 버튼으로 텍스트 QR에 표시; 휴대폰에서 직접 읽고 별도 저장 | 외부 도움 없이 텍스트 QR을 읽고 저장할 수 있는가? |
| 돌아올 때 확인하기 | 앱에서는 같은 기기에서 24시간 안에 메모 재열람·삭제; 수동 복사본은 휴대폰에서 확인 | 같은 방문 안에서 기록을 다시 확인할 수 있는가? 앱 재사용과 폰 복사본 사용을 구분하는가? |

이 단계는 유입·유지율이 증명됐다는 뜻이 아니다. Android 공유수신은 동일 기기의 앱 간 텍스트 전달이며 휴대폰에서 차량으로 자동 전송하지 않는다. Android는 저장한 주차 메모를 일반 텍스트 QR로 표시하는 수동 가져가기 기능을 구현했다. 사용자가 휴대폰에서 직접 읽고 별도로 저장해야 하며 자동 전송·앱 연결·동기화는 없다. QR에는 메모·저장 시각·복사본 만료 안내를 담고, URL·계정·좌표·행사 원문은 담지 않는다. 실제 휴대폰 카메라의 광학 인식 성공은 아직 입증되지 않았다. 웹/휴대폰에서는 해당 기기에 남긴 메모를 안전 확인 후 볼 수 있다. 어느 방식도 차량의 실제 위치를 찾거나 주차장 보행 경로를 안내하지 않는다.

초기 유입 후보는 참가자가 받은 안내문을 직접 공유하는 행동이다. 주최사 제휴와 Pleos App Market 노출은 추가 후보이며 계약·입점·배포량을 확보하지 않았다. 현재 데이터로 예상 MAU·매출을 산정할 수 없으므로 임의 전환율의 숫자 전망은 제시하지 않는다.

## 검증 계획과 지표 정의

실제 고객 인터뷰와 현장 관찰 없이 검증 가능한 것은 안전한 기능 동작, 안내문 분류와 UI 흐름까지다. 아래는 후속 사용자 검증 설계이며 이미 실행한 실험이나 측정 결과가 아니다.

- 입력 완료율: 지원 안내문을 받은 참여자 중 외부 도움 없이 장소 확인 단계까지 도달한 비율. 실패한 안내문 유형을 함께 기록한다.
- 잘못된 확정: 안내문과 다른 행사장·시설 또는 높이 초과 상태를 확정한 건수. 자동시험 결과와 실제 사용자 관찰은 별개로 보고한다.
- 수동 가져가기 과업 완료율: Android에 저장한 메모를 QR로 표시한 참여자 중 자신의 휴대폰에서 내용을 읽고 별도로 저장한 비율. QR 디코드 단위시험으로 대체하지 않으며 카메라 앱·화면 밝기·읽기 거리별 실패를 기록한다. 아직 실제 참여자 결과는 없다.
- 같은 방문의 메모 재열람률: 직접 주차 메모를 저장한 참여자 중 같은 방문 안에 이를 다시 확인한 비율. 새 방문의 재사용률이나 고객 유지율로 바꾸어 표현하지 않는다. QR로 복사한 텍스트를 휴대폰 메모 앱에서 보는 행동은 Arrival Brief 앱 재열람이나 MAU로 세지 않는다.
- 방문 간 재사용률: 두 번째 지원 행사 방문 기회가 있는 참여자 중 재사용한 비율. 후속 방문 여부에 대한 별도 동의·관측 없이 분모를 추정하지 않는다.
- MAU: 월 1회 이상 방문 준비를 확정하거나 저장한 주차 메모를 다시 확인한 순이용자. 브라우저와 Android 이용자를 근거 없이 합산하지 않는다.

현재 제품에는 원격 행동 분석을 넣지 않았다. 계측을 추가한다면 동의, 최소 수집, 중복 처리, 보관 기간과 삭제를 먼저 정한다. 행사 원문·주차 위치 메모를 수집해 지표를 산출하지 않는다. 단위시험 수치나 에뮬레이터 실행 횟수는 사용자 수·유지율·만족도가 아니다.

최근 목적지는 사용자가 저장한 1건의 목적지 ID·시각·자료 버전만 24시간 보관하며, 복구는 안전 확인을 다시 해야 하는 초안이다. 주차 메모도 별도의 최소 기록으로 저장 후 24시간에 만료된다. 앱 활성 상태에서는 만료 감시로 정리하고, 종료 중이었다면 다음 조회·실행 때 정리한다. 종료 중의 정각 자동 삭제를 보장하지 않는다. 수동 QR로 휴대폰에 별도 저장한 복사본에는 앱의 만료·삭제가 적용되지 않는다. QR 표시 전과 QR 텍스트 안에 이 차이를 알린다. 메모가 존재해도 이전 확정·주차 상태를 자동 복구하지 않는다. 실제 구현과 검증 결과는 [검증 기록](HYUNDAI_VERIFICATION.md)을 기준으로 한다.

## 데이터 운영과 확대 조건

자료 운영에는 목적지별 공식 출처, 확인일, 검토 상태, 상충 사유, 갱신 기록이 필요하다. 원문 변경을 사람이 검토하고, 상충 여부와 양쪽 엔진의 안내가 일치하는지 시험한 뒤 갱신한다. 경과일이 짧다는 이유만으로 원문의 정확성을 보증하지 않는다.

1. 먼저 현재 8개 분류의 안내·보류와 갱신 절차를 재현한다.
2. 새 시설은 공식 출처와 재검토 담당 범위가 정해진 경우에만 추가한다.
3. 목적지 수뿐 아니라 미해결 상충 수, 갱신에 드는 시간, 재검토 대기량을 기록한다. 아직 실제 운영 비용은 측정하지 않았다.
4. 공식 정보가 불명확하면 보류 사유와 원문으로 이어지는 경로를 유지한다. 현장 답변을 받지 않은 상태에서 상충을 임의 해제하지 않는다.

운전자 유료 구독 수요나 매출을 가정하지 않는다. 행사 운영자의 안내 배포·자료 검토 기능을 유료 후보로 검토하되, 실제 배포 가능성과 반복 운영 비용이 확인된 뒤 결정한다. 제휴나 고객 인터뷰 없이 구현할 수 있는 것은 데이터 검토 도구·배포 샘플·오류 처리 재현까지다.
