# Arrival Brief 디자인 검토 기록

검토일: 2026-10-31

이 문서는 독립 에이전트가 진행한 **AI 독립 모의 검토**다. 실제 이용자 인터뷰, 사용성 실험, 전문가 인증, 공식 심사 결과가 아니다. 점수나 이용자 성공률을 추정해 기재하지 않는다.

## 검토 범위와 상태

| 단계 | 확인한 것 | 확인하지 않은 것 | 상태 |
| --- | --- | --- | --- |
| 변경 전 코드 검토 | 웹 `dist/arrival/index.html`, `style.css`, `app.mjs`, 공통 브랜드 테마, Android `MainActivity.kt`의 화면 구조와 상태 처리 | 렌더링 화면의 실제 대비·줄바꿈, 실제 차량의 시인성, 터치 정확도 | 완료 |
| 변경 후 코드 재검토 | 새 웹·Android 화면 구조, 미확정 결과 분리, 남은 조건 안내, 보조 정보 배치 | 렌더링의 줄바꿈·가림·스크롤 위치 | 완료, 아래 추가 검토 기록 참조 |

이후 시각 재검토 결과는 아래에 별도로 기록한다. 코드상 개선과 실제 화면에서 확인한 개선을 구분하며, 기존 항목은 근거 없이 완료 처리하지 않는다.

## 변경 전 핵심 판단

장소·높이·자료 상충·차량 상태를 구분하는 기능 구조는 유지할 가치가 있다. 문제는 준비 안내, 데모 조작, 입력, 보관 안내, 출처 설명이 주 작업과 시선을 나누는 구성이다. 핵심 경로 정보와 확인 절차를 앞으로 당기고, 보조 설명은 필요한 위치에서 펼쳐볼 수 있게 정리한다.

검토한 코드에서 확정·주행 잠금을 우회하는 결함을 확인하지 못했다. 이는 해당 기능의 동적 검증 완료를 의미하지 않는다. 디자인 변경 후에도 주행·미확인 상태의 편집 제한, 높이 초과와 자료 상충의 확정 차단이 유지되는지 확인해야 한다.

## P1 개선 항목

P1은 이용 흐름과 차량 화면 적합성에 직접 영향을 주어 이번 개선에서 우선 처리할 항목이다. 아래 상태는 변경 전 코드 검토 시점을 기준으로 한다.

| ID | 확인한 문제와 근거 | 필요한 개선 | 완료 확인 기준 | 상태 |
| --- | --- | --- | --- | --- |
| UX-01 | 웹의 큰 히어로·모드 체험 설명이 입력 작업보다 먼저 배치되고, 하단에도 유사한 사용 설명이 반복됨 | 장소 선택과 브리핑을 첫 화면 중심으로 이동. 체험 모드는 작은 도구 영역으로 정리 | 첫 화면에서 입력과 결과 영역이 구별되고, 일반 사용 흐름에 설명 카드의 반복이 없음 | 코드·웹 화면에서 개선 확인 |

## 보존할 기능 경계

- 자료가 상충하거나 차량 높이가 제한을 넘는 경우, 안내를 확정할 수 없어야 한다.
- 차량 상태가 미확인이거나 입력이 허용되지 않으면 편집·복사·보관 조작을 막는다.
- 주행 화면에는 사용자가 확정한 내용만 남긴다. 미확정 입력을 자동 승격하지 않는다.
- 실제 차량에서는 운영체제가 화면 전체를 제한할 수 있다. 주행 중 앱 화면이 항상 표시된다고 설명하지 않는다.
- 웹의 차량 상태 전환은 시뮬레이션이다. 실제 차량 연결 기능처럼 표현하지 않는다.
- 내비 목적지 대조는 실제 지원 범위에 맞게 설명한다. 연결 불가나 대조 실패를 정상 일치 상태로 바꾸지 않는다.
- 최근 장소 복원은 차량 높이·확인 상태 복원을 의미하지 않는다.
- 검증하지 않은 지리적 방향을 장식용 화살표나 지도처럼 표현하지 않는다.

## 변경 후 코드 재검토 기록

2026-10-31, `dist/arrival/index.html`, `app.mjs`, Android `MainActivity.kt`를 다시 읽었다. 아래는 코드에서 확인한 변경이며 실제 화면의 완료 판정은 아니다.

- 웹은 초기 예시 자동 입력을 없애고 장소 선택을 주 입력으로 배치했다. 안내문 입력·예시·출처·지원 범위는 펼침 영역으로 옮겼다.

- 검토한 변경 코드에서 확정·입력 잠금 우회는 발견하지 못했다. 기능 회귀 테스트와 화면 검토 결과는 별도로 확인해야 한다.
