# RC3 독립 코드·경계 검토

검토일: 2026-11-02 KST. 검토자: `completion_review`. 기준 커밋은 `8ed826c`이며, RC3의 일정·등록 안내 분리와 Android 확정 집중 화면 변경을 읽고 후속 입력을 따로 구성했다. 구현 코드는 수정하지 않았다.

**검토한 소스 범위에서는 새로 재현되는 P1·P2 결함이 없었다.** 후속 challenge 76개를 웹과 실제 Kotlin 소스로 각각 실행해 모두 통과했다. 전체 제품의 완벽함, 실제 Pleos 연동, 물리적 카메라 인식 또는 공모전 수상 가능성을 이 결과에서 추정하지 않는다.

## 개발 예시와 독립 검토의 구분

개발에서 고정한 10개 합성 예시의 RC2 8/10 → RC3 10/10 비교는 개발 회귀 자료다. 이 검토는 그 10개를 결과에 재사용하지 않고 **별도의 원문·조건 76조합**을 작성했다. 다만 구현과 개발 예시를 읽은 뒤 만든 후속 challenge이므로, 맹검·대표 표본·실제 사용자 관찰로 표현하지 않는다. 두 결과를 합쳐 일반적인 정확도나 사용자 성공률을 계산하지 않는다.

[독립 입력별 결과와 소스 해시](award-independent-review.json)에 원문·높이·수동 선택·기대값·웹 결과·Kotlin 결과를 기록했다. scratch의 `award-review/challenge.mjs`와 `AwardChallenge.kt`로 재현했으며 Gradle·에뮬레이터는 실행하지 않았다.

## 확인한 파서 경계

- 정상적인 같은 날 시작·종료 시각, 00시·23시 경계, 등록 전용 로비 문장, 두 종류의 동시 입력, 같은 원문의 반복과 글머리표를 확인했다.
- 허용한 일정·등록 원문은 따로 남고 실제 텍스트 내보내기에도 보존됐다. 일정만으로 현재 개최 중이라고 주장하지 않으며 등록층은 행사장 층·실내 경로와 구분한다.
- 정상 문장 뒤에 취소·종료·다른 시설·장소 변경·주차 불일치·출입 금지·시설 높이 제한을 붙이면 보류했다. 수동으로 기존 행사장을 선택해도 우회하지 못했다.
- 등록층 0·앞자리 0·소수·지하·지원 밖 층, 다른 시설이 섞인 등록 문장, 불명확한 긍정/부정·질문 문장과 서로 다른 등록 안내는 보류했다.
- 같거나 역전된 시작·종료 시각, 범위를 벗어난 시·분, 완료형·질문형·느낌표·행 분리·상충 일정은 허용 예외가 되지 않았다.
- 정상 일정·등록 문장이 있어도 차량 높이 누락·초과·오류, 공식 자료 상충과 다른 수동 목적지는 확정할 수 없었다.

이번 예외 문법은 절 전체가 좁은 형식과 일치해야만 적용된다. 원문 전체의 다른 시설·변경·취소·운영 검사를 삭제하지 않은 점도 코드로 대조했다. 따라서 임의의 자연어를 모두 이해하는 기능이라는 주장은 할 수 없지만, 검사한 문장에 숨어 있는 제한을 예외가 지우는 재현은 없었다.

## 확정 집중 화면과 상태 게이트

`MainActivity`의 실제 클릭 처리·렌더링·복귀 처리와 해당 instrumentation 코드를 읽었다.

- 확정 후 준비 입력을 숨기고 확정 패스를 보여준다. `안내 수정`은 현재 입력 허용을 다시 검사하며, 확정본과 행사장·높이·주차 확인을 모두 해제한다.
- 주행·UNKNOWN 및 백그라운드 전환 후에는 이전 확정값을 표시할 수 있어도 복사·보관 조건이 자동 복구되지 않는다. 허용 상태로 돌아온 뒤 명시적으로 수정·재확인해야 다시 내보낼 수 있다.
- 복사·목적지 보관 클릭은 현재 `canExport`를 다시 검사한다. 지연된 수정 클릭도 입력 제한 중이면 준비 화면을 열지 않는다.
- 일정·등록 원문 보기 동작도 현재 입력 허용을 검사하며, 입력 제한 상태에서는 해당 세부 원문을 새로 펼칠 수 없다.

현재 Kotlin 엔진·세션을 별도 컴파일해 동일한 76개 입력의 판단과 실제 `confirm`·`canExport`를 검사했다. 추가로 차량 모드·시뮬레이션 여부·3개 확인값 조합, 잠금 복귀와 명시 수정 후의 재확인을 실행했다. 이는 실제 `MainActivity` 화면이나 플랫폼 서비스의 실행을 대체하지 않는다. 실제 화면의 배치·스크롤·큰 글자·stale click 검증 결과는 담당 런타임 보고서를 따른다.

| 검사 | 통과 결과 | 수치의 의미 |
| --- | ---: | --- |
| 독립 웹 challenge | 76/76 | 후속 원문·조건 조합 |
| 같은 입력의 Kotlin challenge | 76/76 | 동일 입력의 실제 Kotlin 판단·원문 보존·상태 게이트 |

동일 76입력을 두 구현에서 실행했으므로 152개의 고유 시나리오라고 합산하지 않는다. 소스 해시는 연결한 JSON에 기록했으며, 검사 중 변하지 않았음을 확인했다. 이후 관련 소스가 바뀌면 해당 범위를 다시 대조해야 한다.

새 APK의 서명·설치·실행 및 화면 검증, Pleos SDK 실제 응답·차량 UX 제한 전환, 실물 QR·실차·사용자 효과는 이 독립 코드 검토의 성공 항목에 포함하지 않았다.
