# RC2 최종 독립 검수

검토일: 2026-11-02. 검토자: `final_acceptance`. 최종 소스의 숫자 층 판정과 제출 근거의 정합성을 별도로 검토했다. 구현 담당자와 별개로 실패 입력을 실행하고 수정 후 같은 입력을 재검증했다. 제품 전체에 점수를 부여하거나 100점을 선언하지 않는다.

## 추가 발견과 수정

**P2 — 비정상 지하층·숫자 층 토큰을 무시하는 잔여 경계**를 발견했다. 예를 들어 `코엑스 오디토리움 B03층`, `B0층`, `B-3층`, `B 3층`에 오디토리움을 선택하면 기존 RC2 수정본은 `ready`, `canConfirm=true`였다. 지하층 검사에서 정수 `B3`만 인식하고 일반 층 검사에서 `B` 뒤 숫자를 제외하면서 비정상 토큰이 판단에서 빠졌다. `.3층`, `3.층`, `＋3층` 및 숫자 구분자·분수·지수 형태에서도 같은 부분 해석 문제가 재현됐다.

구현 담당자는 양쪽 엔진에서 B 접두와 공백·부호·앞뒤 소수점·쉼표·분수·지수 형태를 전체 숫자 토큰으로 잡도록 수정했다. 정상 지상층은 앞자리 0이 없는 양의 정수 표기만 허용하며, 나머지 토큰은 다른 장소의 수동 선택으로 덮어쓸 수 없게 보류한다. 원문을 변경하거나 버리는 처리는 추가하지 않았다.

## 독립 재검증

[입력별 결과와 소스 해시](completion-final-acceptance.json)를 남겼다.

- 고정 토큰 **55개**: 정상 표기 5개와 보류해야 할 50개. 초기 메시지의 “54개”는 수기 개수 착오였으며 실제 실행 목록은 55개다.
- 정상 표기 `3층`, `3F`, `3 F`, `3 층`, `3층 3F`를 보존했다. 같은 형태를 1층·2층 장소에도 적용했다.
- 3개 장소(오디토리움·그랜드볼룸·아셈볼룸) × 2개 입력 경로(명시 장소·수동 선택) × 55개 토큰으로 **330개 조합**을 실행했다. 정상 허용 30개와 보류 300개다.
- 웹 **330/330 통과**: `buildBrief.canConfirm`과 모든 확인 체크를 켠 `reviewAllowsConfirmation` 결과가 일치했다.
- 실제 Kotlin 소스 7개를 별도 JVM에서 컴파일한 검사도 **330/330 통과**했다. 각 입력의 `resolve`, `canConfirm`, 실제 `confirm`, `canExport` 결과를 확인했다. 웹 결과를 반환하는 대체 엔진을 사용하지 않았다.
- 앞선 독립 검토의 영문 회의실·층 입력 87개도 마지막 숫자 토큰 수정 뒤 웹과 새 Kotlin 클래스에서 각각 **87/87 재통과**했다. 앞선 보고서의 당시 소스 해시는 바꾸지 않고 이번 재검증을 별도 기록했다.

웹 엔진 SHA-256은 `3eed7385f221e7098e325a40dda35180d2805cb0a24ff82a0ab74250a693b375`, Kotlin 엔진은 `3b471854725bc3bb270e80891f88f8dd2962519abbe19ee61e89d40d90a381da`다. 이번 추가 결함군의 고정 검사 범위에서 남은 실패는 없다. 이 결과를 원래 공통 사례 수나 단위시험 수에 더해 기능 수처럼 표시하지 않는다.

## 판정 범위

이 검사는 숫자 층 토큰의 같은 결함군으로 범위를 고정했다. 모든 미지의 자연어·시설명·등록 장소를 이해한다는 뜻은 아니다. 정상 안내의 시설·층·현재 행사 여부를 사람이 확인하는 제품 흐름을 유지한다.

소스 회귀 검사와 아래 최종 APK·화면·미디어 대조는 통과했다. 현재 소스와 다른 이전 APK의 실행 결과를 새 빌드의 성공으로 옮기지 않았다. 실제 Pleos SDK 응답·차량 UX 전환·휴대폰 카메라의 광학 QR 스캔은 이번 검사에 포함하지 않았다.

## 전달 검수

[최종 런타임 기록](android-runtime-rc2.json), [빌드 입력](build-inputs.json), [릴리스 결과](release-verification.json)를 실제 파일과 대조했다.

- 최종 RC2 APK는 6,659,947바이트, SHA-256 `779d69f709e16a9ec2a4ffb9de235d908f442c4f8dd25bc80fd574c12d003f0f`다. 저장소의 APK 3개 복사본과 기기 설치본 해시가 일치한다. 빌드 입력 43개와 현재 소스가 일치한다.
- 일반 AOSP Android 9에서 기존 RC1의 업데이트 설치와 첫 실행을 확인했다. 별도 debug APK의 표준 UI **16/16**, 글자 크기 1.3배 반복 **6/6**이 통과했다. Android 단위시험 74개·웹 55개·공통 판단 입력 387건과 근거 파일의 수가 일치한다.
- 현재 캡처 30장의 해시를 대조했다. 표준·큰 글씨 QR 화면에서 QR 전체와 닫기 버튼을 직접 확인했다. B03 화면은 원문과 확인 체크를 보존하면서 확정을 막았다. 캡처를 실제 Pleos 화면으로 표시하지 않는다.
- 웹 편집 영상 2편과 Android 편집 영상 1편은 모두 **30초·1280×720**이다. 현재 소스·원본 캡처·영상의 해시가 metadata와 일치한다. Android 원본 연속 녹화도 해시와 실제 길이 **179.083833초**가 일치한다. 편집 영상을 연속 녹화로 표시하지 않는다.
- 승인된 생성 아이콘 원본은 기준 커밋 `203841c`와 바이트가 같다.

릴리스 실행 로그의 **OS `cmd` 프로세스 SIGSEGV 1건**을 별도 검토했다. 실패 PID는 3164이고 앱 PID 3166과 다르다. 앱의 표시 완료와 이후 렌더 로그, `Status: ok`, 기기 설치 해시를 직접 대조했다. 표준·큰 글씨 UI 로그에는 fatal/ANR 시그니처가 없으며, 세 로그 구간에서 앱 관련 시그니처는 관찰되지 않았다. 원문을 보존한 [로그 분류](android-aosp28-rc2-log-review.json)에서 근본 원인을 미확정으로 남겼다. 환경 전체가 크래시 없이 동작했다고 주장하지 않는다.

[최종 QR 검사](completion-qr.md)의 두 원본 화면과 source 해시를 직접 대조했다. 표준 화면은 jsQR에서 원문이 일치했지만 OpenCV는 읽지 못했고, 큰 글씨 화면은 두 디코더 모두 일치했다. 원본 화면 기준 **3/4 판독**, 잘못 읽힌 비어 있지 않은 결과는 0건이다. **독립 QR 호환성 시험을 전부 통과한 상태는 아니다.** 엄격 검사 종료 코드 1을 유지했다.

원본 QR 영역에 흰 여백 40px를 붙인 진단에서는 4/4가 읽혔지만 이를 앱 원본 화면 성공으로 합산하지 않았다. 별도의 고정 소스 표본 60/60, 모의 변형 380/420 결과도 원본 화면·실물 카메라 검사와 구분했다. 실제 휴대폰의 광학 판독과 모든 스캐너 호환성은 확인되지 않았다.

이 공개 보고서의 검사 범위는 위 소스·런타임·미디어·QR 증거까지다. 이후 생성되는 검토 ZIP 자체의 해시·포함 파일 대조는 별도 전달 검수로 수행한다. 이 문서가 포함되는 ZIP의 해시를 본문에 다시 넣어 자기 참조를 만들지 않는다.
