# RC2 추가 독립 품질 검토

검토일: 2026-11-02 KST. 검토자는 `completion_review`, Android 상태 게이트 보조 검토자는 `native_gate_audit`다. 이전 평가 점수에 맞추지 않고 기준 커밋 `203841c`의 코드·현재 화면 자료를 새로 읽고 경계 입력을 직접 실행했다. 앱 구현은 수정하지 않았으며 발견 사항은 구현 담당자에게 전달한 뒤 수정본을 독립 재검증했다.

**이번에 발견한 P1·P2 결함군은 수정 후 재검증을 통과했다.** 이 판정은 아래 소스·순수 JVM 검사 범위다. 새 APK의 설치·실행, Pleos SDK 응답, 실물 카메라·실차 시험을 대신하지 않으며 전체 제품에 임의의 100점을 부여하지 않는다. 기존 88점도 이번 결과만으로 자동 승격하지 않는다.

## 발견 사항과 수정 확인

| 항목 | 기준 커밋에서의 직접 재현 | 영향 | 수정 후 확인 |
| --- | --- | --- | --- |
| P1 — 영문 회의실 번호의 수동 선택 우회 | `COEX Room 300 3F`에 `auditorium`을 수동 선택하고 높이 `1.65`를 넣으면 `ready`, 확정 가능이었다. `Room 301`, `Room No. 301`, `Room #301`, `Room: 301`과 번호 뒤 접미사도 검사했다. | 원문에 있는 회의실 번호가 목적지 후보에서 누락돼, 공식 자료 상충으로 보류할 회의실을 다른 장소로 바꾸어 확정할 수 있었다. | Room/Rooms·No./number·번호 구분자를 양쪽 엔진에서 분류한다. 알려진 300·400번대는 해당 목적지의 자료 상충을 유지하며 다른 수동 선택은 차단한다. 불명확한 접미사·지원 밖 번호는 보류한다. |
| P2 — 층 토큰의 일부만 해석 | `코엑스 그랜드볼룸 -1층`, `코엑스 오디토리움 -3층`, `0층`, `01층`, `0.3층`이 정수 꼬리만 읽히거나 무시되어 확정 가능했다. | 음수·0·비정상 층 표기를 정상 지상층과 같은 것으로 해석했다. | 부호·앞자리 0·소수를 포함한 전체 토큰을 검사한다. 비정상 토큰은 보류하며 정상 1/2/3/4층과 F 표기는 유지한다. |
| P3 — 주차 메모의 문자 상한 불일치 | 웹 정책은 64개 코드 포인트를 허용했지만 HTML `maxlength`와 Android는 UTF-16 64단위였다. | 정책 시험에서 허용한 이모지 길이가 실제 입력 상한과 달랐다. | 웹 정책을 실제 UI·Android의 UTF-16 64단위와 맞췄다. 한글·ASCII 64단위와 자동차 이모지 32개는 허용하고 각각 초과 입력은 거부함을 직접 확인했다. |

첫 번째 수정본의 후속 검사에서 `Room #301` 우회를 추가로 발견해 전달했다. 최종 코드에서는 `#`, `:`, `No:`, `№`도 포함해 이 결함이 닫혔다. 새로운 미지의 자연어를 모두 이해한다는 뜻은 아니다. 안내문의 시설·층·현재 행사 여부는 제품 흐름대로 사람이 확인해야 한다.

## 독립 실행 결과

[입력별 결과와 검사 소스 해시](completion-independent-evidence.json)에 기준판과 수정판을 기록했다.

- 87개의 원문·선택 조합을 별도로 구성했다. 기준 커밋의 웹 엔진은 37조합에서 기대한 차단을 하지 못했고, 수정판은 **87/87 통과**했다. 37은 같은 두 결함군의 입력·선택 조합 수이며 독립 기능 37개가 아니다.
- 같은 87입력을 현재 Kotlin 엔진·세션에 넣어 판단, `canConfirm`, 실제 `confirm`, `canExport`까지 **87/87 통과**했다. 웹 결과를 그대로 반환하는 대체 구현을 쓰지 않고 현재 Kotlin 소스를 별도 컴파일했다.
- 별도 7개 Kotlin 소스의 상태 조합 검사 **12,424 assertion이 통과**했다. 차량 연결 세대, 취소·지연 콜백, 내비 불일치 유지, 복구·복귀 후 재확인, 내보내기 게이트를 검사했다. 이는 상태 조합 assertion 수이며 테스트 기능 수나 실제 SDK 실행 수가 아니다.
- 메모 길이의 독립 경계 assertion **6개 통과**. 실제 입력 상한을 늘리지 않았으므로 QR의 최대 메모 바이트를 추가로 늘리지 않는다.

검사한 최종 웹 `engine.mjs` SHA-256은 `3eed7385f221e7098e325a40dda35180d2805cb0a24ff82a0ab74250a693b375`, Kotlin `BriefEngine.kt`는 `3b471854725bc3bb270e80891f88f8dd2962519abbe19ee61e89d40d90a381da`다. 다른 상태 클래스의 해시는 연결한 JSON에 기록했다. 이후 소스 변경이 있으면 해당 결과와 범위를 다시 대조해야 한다.

## 최종 수용 검토 후 재확인

별도 최종 수용 검토가 B03층·B0층과 소수점 선행·전각 부호·쉼표·분수·지수 형태의 층 표기에서 남은 경계를 발견했다. 그 보완 후 이 검토의 기존 87입력을 웹과 Kotlin에 다시 실행해 각각 87/87 통과했고, 순수 JVM 상태 assertion 12,424개도 다시 통과했다. 입력 목록을 바꾸거나 실패 사례를 제외하지 않았다. 새로 발견된 층 표기의 재현·해결 평가는 별도 최종 수용 검토의 범위이며, 이 보고서의 새 발견으로 중복 계산하지 않는다. 이전 소스 해시와 검증 요약은 증거 JSON의 `verification_history`에 보존했다.

## 화면·데이터 경계 검토

기존 실제 Android 확정 화면과 종료 상태 보류 화면을 직접 열어 확인했다. 승인된 생성 아이콘과 밝은 준비 영역·짙은 확정 패스의 구분을 유지할 수 있다. 확정 화면은 목적지·진입문·추천 주차의 위계가 명확하다. 보류 원문이 화면에 남고 비활성 확정 버튼과 함께 표시된다. 원문 처리·렌더링·브라우저 저장·복귀 경로도 읽었으며, 이 검사 범위에서 추가로 재현한 중대 결함은 없었다.

보류 설명은 여전히 길고 실차 시청 거리에서의 시인성은 관찰하지 않았다. 이번에 확대되는 QR 표시와 축약되는 payload의 실제 화면·독립 디코드 결과는 별도 QR·런타임 기록을 따라야 한다. 기존 화면을 RC2의 새 QR 화면처럼 제시하지 않는다.

Manifest는 Navi 목적지 권한만 선언하고 앱 백업·기기 간 전송을 차단한다. 원문·차량 높이·내비 주소를 저장하지 않는 구조와 주차 메모의 별도 만료 규칙을 확인했다. 휴대폰에 복사된 텍스트까지 앱에서 삭제할 수 있다는 주장은 하지 않는다.

## 최종 완료 판정의 경계

이 보고서의 코드 수정 검토는 통과다. 하지만 새 APK 설치·실행 및 배포 파일과 소스의 일치는 최종 release/runtime 자료에서 별도로 확인해야 한다. 실제 Pleos 목적지 응답·차량 UX 제한 전환, 실제 휴대폰의 광학 QR 판독, 실차 환경과 실제 사용자 효과를 이번 순수 코드 검사에 포함하지 않았다. 이 근거가 없으면 해당 항목을 성공으로 바꾸거나 제품 전체가 완벽하다고 선언할 수 없다.
