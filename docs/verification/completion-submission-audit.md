Pleos 실기·실차 미검증을 1차 서류 접수 불가 조건으로 확대하지 않는다. 반대로 1차 제출 자료가 있다는 이유로 차량 환경의 동작까지 완료됐다고 주장하지 않는다.

## 파일 점검 결과

- 공식 양식의 참가 구분·부문·필수 연락정보가 입력되어 있다. 운영 접수용 표와 동의 표 XML, 서명 이미지 바이트는 사용자가 승인한 기존 원본과 동일하다. 동의 여부와 기존 서명일을 임의로 다시 쓰지 않았다.
- 신청서의 작품 소개 영역에 참가자 연락처·이메일이 들어 있지 않다. 서명된 신청서, 연락처, 서명키는 공개 저장소와 익명 검토 ZIP에서 제외한다.
- 공식 제출용 APK는 저장소 `apk/` 아래 지정 파일명 형식으로 존재한다. 일반 다운로드용 파일과 SHA-256이 같으며 release 서명·설치·실행 근거를 별도로 보관한다.
- README에 앱의 목적, 실행법, 테스트 환경·설정, APK 위치가 들어 있다. 소스와 APK를 함께 제공하므로 APK만 단독 전달하는 구성은 아니다.
- `minSdk 28`, Kotlin, Gradle 8.13 구성은 공식 개발 환경의 API 28 이상·Gradle 8 이상·Java/Kotlin 조건을 충족한다. 이것은 Pleos 서비스의 실제 응답을 검증했다는 뜻이 아니다.
- 영상 3편은 화면 캡처 편집본임을 명시하고 웹 시뮬레이션·일반 Android 자동 UI 시험·release 설치 근거를 구분한다. 영상 제출 규정은 목업·프로토타입·화면 녹화를 인정한다.
- 기본 메일 첨부는 서명된 PDF·동일 내용의 DOCX·공식명 APK로 통일한다. 소스·검토 ZIP·영상은 공개 저장소 링크로 제공한다. 전체 준비 ZIP과 개별 파일을 중복 첨부할 필요가 없다.

## 발견 후 정리한 불일치

신청서의 검토 ZIP 전달 표현이 메일 초안의 링크 제공 방식과 달랐다. 최종 문서에서 “함께 제공”으로 맞췄고, PDF/DOCX 중 어떤 것을 보낼지 다시 판단해야 하는 안내를 기본 첨부 3종으로 정리했다. 이 변경은 기존 동의·서명·서명일을 변경하지 않는다.
