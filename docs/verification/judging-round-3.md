# 독립 심사 3 — Arrival Brief 1.0.0-rc1

심사일: 2026-11-01 UTC. 심사자: 새 독립 심사 에이전트 `judge_round3`.

**첫 평가: 65/100.** 안내를 확인 가능한 도착 패스로 만드는 시각적 완성도와 보수적인 기본 잠금은 좋다. 그러나 처음 검토한 후보에서는 일상적인 다른 행사장·연기 표현으로 잘못된 브리핑을 확정할 수 있었고, 차량에 기록한 위치를 차 밖에서 읽을 수 없어 차량용 제품의 귀가 흐름이 끝까지 이어지지 않는다. 제출 후보의 완성도는 개선이 필요하며, 차량 실증을 마쳤다는 판정은 할 수 없다.

이 점수는 공식 공모전 가중치가 아닌 요청된 내부 고정 루브릭을 사용했다. 이전 심사 보고서·점수는 읽지 않았다. 검토 도중 병렬 수정이 시작되었으므로 **최초로 관찰한 후보의 평가를 유지**한다. 뒤에서 착수한 QR 기능이나 보고 이후 파서 보완은 이 점수에 가산하지 않는다. 후속 독립 심사는 최종 동결 소스와 APK로 별도 수행해야 한다.

## 검토 범위와 직접 관찰

읽은 주요 자료는 `docs/PRODUCT_SCOPE.md`, `docs/USER_EVIDENCE.md`, `android/README.md`, 웹 `dist/arrival/{engine,app,visit}.mjs`와 HTML/CSS, 랜딩, Android의 MainActivity·BriefEngine·BriefSession·공유/메모 정책·차량 gateway·내비 reader 및 관련 manifest다. 범위 문서는 구현과 가설, 미지원 기능을 대체로 정확히 분리한다.

새 브라우저 탭 7에서 `http://terminal.local:4173/` → `/arrival-brief/` → `/arrival/`를 검토했다. 랜딩과 앱을 실제 화면으로 보았고, 다음을 직접 관찰했다.

- 랜딩은 휴대폰·차량 동기화 미지원, 차 밖에서는 휴대폰 웹에 직접 기록해야 한다는 조건을 Hero에 표시한다. 0.5.0 시연 영상임도 명시한다.
- 다른 최종 행사장이 적힌 문장을 입력한 뒤 높이 1.65m, 높이·주차 체크를 하면 확정 버튼이 활성화된다. 클릭하면 `✓ 확정됨`, `북문`, `B3 블루존`과 저장/복사 버튼이 실제 표시되었다. 아래 P1-01의 첫 문장이다.
- 주행 모드는 입력 및 메모를 감추고 확정된 핵심 안내만 남겼다. 정차로 돌아오면 주차 체크가 풀리고 저장·복사가 다시 잠겼다.
- 주차 메모는 별도 주차 확인 전 감춰져 있었다. 확인 뒤 기존의 실제 위치 기록이 추천 주차와 별도 영역에 표시되었고, 페이지 재로드 후 다시 감춰졌다. 이 심사에서는 기존 메모를 덮어쓰거나 삭제하지 않았다.
- `node --test tests/*.test.mjs`를 직접 실행하여 최초 검토 시점 29개 통과, 실패 0개를 확인했다. 이는 아래의 새 자연어 반례를 포괄했다는 뜻은 아니다.

비동기 TXT 가져오기는 소스에서 generation 토큰과 입력·확정·모드·페이지 전환 시 무효화를 확인했다. 파일 읽기 지연을 조작한 브라우저 경합시험은 이 심사에서 수행하지 않았으므로 실행 통과로 쓰지 않는다.

## P1-01 — 다른 최종 행사장·연기 안내를 기존 지원 장소로 확정

처음 읽은 엔진과 현재 preview에서 발견한 정확성 결함이다. 발견 즉시 root에 재현과 수정 제안을 보냈다.

| 입력 | 최초 엔진 결과 |
| --- | --- |
| `코엑스 오디토리움 3층. 이번 행사는 한빛센터에서 합니다.` | `matched`, `ready`, `canConfirm=true`; 실제 웹 UI에서 확정 완료까지 재현 |
| `코엑스 오디토리움 3층. 행사는 더 이상 열리지 않습니다.` | `matched`, `ready`, `canConfirm=true` |
| `코엑스 오디토리움 3층 행사. 본 행사는 다음 달로 미뤄졌습니다.` | `matched`, `ready`, `canConfirm=true` |
| `코엑스 오디토리움 3층. 최종 개최지: 한빛센터.` | `matched`, `ready`, `canConfirm=true` |
| `코엑스 오디토리움 3층 행사를 줌 온라인으로 전환했습니다.` | `matched`, `ready`, `canConfirm=true` |

엔진 재현은 `buildBrief({text, height:'1.65', mode:'parked'})`다. UI 재현은 안내문 입력 → 1.65 입력 → 높이 확인·안전 주차 확인 → `도착 브리핑 확정`이다. 원문은 기존 지원명을 언급하지만 실제 장소 또는 행사 유효성이 달라졌는데도 북문·B3 블루존을 완성된 패스로 보여주었다. 당시 상태 문구는 `공식 시설 안내와 일치하는 장소를 찾았습니다.`였다. 사용자 체크 두 개는 높이와 주차이며 실제 행사장 확인 체크는 없었다.

수정 제안은 양쪽 엔진에 자연스러운 연기·미개최·개최지·`에서 합니다`·온라인 전환 표현을 보류하는 공유 사례를 추가하고, 인식 결과를 **장소명 후보**로 표현하며 실제 유효한 행사장을 사람이 확인하도록 하는 것이다. 정규식 몇 개 추가로 자유문 전체의 의미 이해가 증명되지는 않는다. 실제 행사 원문을 이용한 별도의 실패 유형 평가가 필요하다.

심사 도중 이 보고에 따른 소스 수정과 공유 corpus 추가가 시작된 것을 확인했다. 수정 전 실제 관찰을 기록한 이 점수를 사후 덮어쓰지 않는다. 새 UI·양쪽 엔진·최종 APK의 회귀와 후속 독립 심사로 종료해야 한다.

## P1-02 — 차량 메모의 차 밖 재열람 공백

이는 숨겨진 구현 버그나 문구 기만으로 판정한 것이 아니라, **차량용 제품의 핵심 사용 흐름 결손**이다. 문서와 Hero는 제약을 정직하게 밝힌다.

최초 후보의 실제 기능은 해당 기기의 직접 메모 1건을 24시간 저장·재열람하는 것이다. 차량에서 기록하고 사람이 차를 떠나면 차량 화면의 메모를 볼 수 없다. 이미 차에 돌아온 뒤에만 읽을 수 있는 메모는 그 차를 찾는 문제를 해결하지 못한다. 휴대폰 웹에 별도 입력하면 그 휴대폰에서는 볼 수 있지만 차량 메모가 연결된 것은 아니다. 폰→차량 안내 가져오기 역시 같은 Android 기기 ACTION_SEND를 넘어가지 않는다.

따라서 주차 위치 기능의 존재나 제한을 설명하는 문구의 개선만으로 “방문 전후가 이어진다”는 차량 제품 목표를 완료로 볼 수 없다. 실제 반출/재열람 기능 또는 차량 안에서만 성립하는 별도의 명확한 사용 가치를 구현하고 검증해야 한다. QR 반출은 이번 평가 중 새로 착수한 계획이므로 완료·가산 대상이 아니다.

## P2 — 안내문 회복과 네이티브 접근성

1. **평범한 주차 문장의 회복 안내가 불충분하다.** `코엑스 오디토리움 3층에서 열리는 정기총회입니다. 주차는 B3 블루존을 이용해 주세요.`와 `장소: 코엑스 오디토리움 3층\n주차: B3 블루존 이용 바랍니다.`가 최초 시험에서 `needs_review`였다. 이미 별도 문장 또는 `주차:` 줄인데도 별도 문장/줄로 다시 입력하라고 한다. 안전 보류는 합리적이지만 왜 실패했는지와 안전한 재작성 예시가 필요하다. 임의 미지원 문구를 무조건 제거하는 해결은 피해야 한다.
2. **네이티브 결과 전달의 보조기술 검증이 없다.** MainActivity는 확정 뒤 스크롤을 이동하고 결과 뷰를 재생성하지만 결과에 accessibility focus 또는 live region을 지정하지 않는다. 메모 저장 성공·오류도 상태 TextView 변경이다. TalkBack 사용자가 변화를 듣고 결과에 도달하는지 실제 검증해야 한다. 소스 관찰만으로 사용 불가라고 단정하지 않는다.
3. **큰글씨에서 그림 속 라벨은 그대로다.** ArrivalSceneView의 캔버스 라벨은 고정좌표·크기이고 fontScale을 따르지 않는다. 핵심 정보가 일반 TextView에도 반복되므로 현재 기능 차단으로 보지는 않는다. 주 레이아웃은 `screenWidthDp / fontScale`을 고려해 세로 배치로 전환하고 64dp 최소 버튼 높이와 가변 높이를 쓰므로 소스 설계는 합리적이다. 키보드·가로·확대 글꼴의 전체 동작 성공은 별도 실증이 필요하다.

## 다음 독립 심사에서 확인할 것

- P1 반례가 양쪽 엔진에서 보류되고 수동 장소 선택으로 우회되지 않는지, 정상 안내는 유지되는지 확인한다.
- 새 행사장 확인 UI와 잘못된 인식에서의 회복을 실제 웹·네이티브 흐름으로 확인한다.
- 반출 기능을 추가했다면 저장된 실제 메모만 사용자 의도로 안전한 상태에서 표시하고, 실제 휴대폰에서 읽고 나중에 재확인할 수 있는지 검증한다. QR가 그려진 것만으로 차 밖 사용 성공으로 판단하지 않는다.
- 동결한 최종 APK의 해시·설치 버전·실행 기록을 묶고, 완료되지 않은 Pleos/사용자 현장 검증은 별도 잔여 항목으로 남긴다.
