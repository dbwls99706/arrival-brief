# Arrival Brief 4차 심사 기록

평가일: 2026-11-01. **본 회차 점수는 81/100**이다. 아래 고정 내부 루브릭으로 판단했으며, 공식 공모전 배점이나 수상 가능성을 뜻하지 않는다.

## 평가 대상과 증거 경계

이 기록은 `1.0.0-rc1`, versionCode `10`, **5,579,851 bytes**인 다음 Android release 후보와, 그 시점의 웹 36개 시험·공유 판정 153개를 대상으로 한다.

```text
SHA-256 a10b1f7ea7f93010b01553468822581300bd1558864a878c2ea8fdc58870c5a6
```

후속 심사에서 발견한 새로운 입력, 이후 수정된 엔진, 다른 APK 해시의 결과는 이 회차 점수에 소급하여 합치지 않는다. 저장소의 일반 증거 파일은 후속 후보로 갱신될 수 있으므로 이 해시와 아래 기록한 실행 결과가 본 회차의 기준이다. 이 기록은 최종 출품물 전체에 대한 무결점 선언이 아니다.

`docs/PRODUCT_SCOPE.md`와 `docs/USER_EVIDENCE.md`를 먼저 읽고, 엔진·세션·공유수신·차량 입력 제한·주차 메모·QR·Activity 수명주기·시험 코드를 검토했다. 최신 웹 화면에서 실패 입력과 수정 결과를 직접 조작했으며, Android 실행 로그와 일반 글꼴/1.3배 글꼴 캡처를 직접 읽었다. 원본 코드는 수정하지 않았다.

이전 심사 보고서 파일은 열지 않았다. 다만 협업 인력 상태를 조회하는 도구 응답에 이전 심사의 짧은 결론과 점수가 자동 노출되었다. 따라서 완전한 블라인드 심사라고 표현하지 않는다. 아래 판정의 근거는 이번에 확인한 코드·화면·실행 증거이며, 기존 점수를 목표로 삼지 않았다.

## 남은 작업의 구분

코드·화면 안에서 계속 개선할 수 있는 것은 보류된 원문의 해결 조건을 더 쉽게 설명하는 일, 안전상 필요한 문구를 유지하면서 확인 부담을 줄이는 일, 실제 TalkBack 과업으로 동적 결과와 QR 조작의 접근성을 점검하는 일이다. 이는 이 회차에서 새로 확정한 P0/P1 목록이 아니라 제품 마찰과 검증 부족에 대한 개선 항목이다.

외부 환경이나 실제 참여자가 필요한 것은 다음과 같다.

- 지원 Pleos 환경에서 설치, NaviHelper 목적지 응답, 입력 허용/주행/연결 해제 전환을 실제 확인한다. OS 부팅 실패를 앱 결함으로 단정하지도, 일반 Android 성공으로 대체하지도 않는다.
- 실물 휴대폰 카메라로 한국어 메모 QR을 읽고 별도로 저장하는 과업을 수행한다. 기종·밝기·거리와 실패를 기록한다.
- 목표 사용자에게 기존 공식 안내/내비와 비교한 과업을 수행하게 하고, 오확정·완료 시간·같은 방문의 재열람을 관찰한다. 이후 방문 재사용·매출·제휴는 별도 증거가 필요하다.
- 공식 자료 상충의 우선 기준을 시설에 확인하고, 정보 변경을 검토·갱신하는 실제 운영 비용을 측정한다.

## 공개 근거 대조

심사자는 다음 원문을 직접 열었다. 일반차량 안내의 지원 장소·높이·진입문·주차 추천과, 2026-02-11 공지의 E/300/400 분류 상충이 제품 문서의 설명과 부합했다. 카카오모빌리티 공식 소개에도 코엑스 POI별 게이트 추천과 주차 위치 기록이 있어, 이 앱의 차별성은 안내문 검토와 보류·기록의 연결 과정으로 한정해 평가했다. 공개 소개만으로 현재 모든 기기에서의 경쟁 서비스 동작이나 이 앱의 우위를 추정하지 않았다.

100점을 주지 않은 핵심 이유는 미구현 기능 수가 아니라, **차 밖에서의 실제 가져가기, 목표 차량 연동, 사용자에게 주는 차별 효과가 아직 입증되지 않았기 때문**이다. 소스 수정 횟수나 자동시험 통과 수를 그 증거로 바꾸어 채점하지 않았다.


이 회차 후보의 빌드 입력·실행 로그·화면 해시는 [a10b 후보 이력](arrival-rc1-candidate-a10b-evidence.json)에 보존했습니다. 현재 후보의 일반 파일명이 갱신되어도 이 회차 판정에는 이 이력을 사용합니다.
