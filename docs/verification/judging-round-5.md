## 직접 확인한 내용

### 웹·소스

새 탭의 `/arrival/`에서 오디토리움을 선택하고 높이 1.65m를 입력한 뒤 세 확인 항목을 체크해 도착 패스를 확정했다. 확정 뒤 북문·B3 블루존이 표시되고, 초안과 확정 결과의 시각적 구분이 뚜렷했다. 별도 메모 `B3 블루존 J5 기둥`을 저장하고 주행으로 전환했을 때 입력·메모가 숨겨졌으며, 정차 복귀 후 재확인해야 메모를 읽을 수 있었다. 다시 읽기와 삭제도 직접 확인했다. `/arrival-brief/`의 최신 소개에서 동일 기기 공유, 수동 QR, 휴대폰 복사본의 별도 보관, 광학 인식 미검증 안내를 확인했다.

추가 브라우저 조작 중 자동화 도구가 두 차례 시간 초과했다. 이를 앱 오류로 판정하지 않았고, 완료되지 않은 추가 웹 UI 시험은 성공으로 세지 않았다. 이후 판단은 직접 소스 검토, Node 실행, Android 원시 증거 확인으로 보완했다.

## 이 심사에서 발견하고 해결을 확인한 항목

**회의실 선택이 현재 원문을 지우던 문제.** 처음 검토한 MainActivity의 picker는 선택할 때마다 안내문을 `코엑스`로 바꿨다. 따라서 모순 주차 안내로 보류된 상태에서 단순한 ‘회의실 선택’을 하면 검토 대상 원문이 사라지고 새 수동 초안이 될 수 있었다. 발견 당시에는 소스 경로로 확인한 P1 후보로 보고했고, 실제 기기를 직접 조작해 재현했다고 표현하지 않았다.

a10b 후보에서는 안내가 비어 있을 때만 기본 시설명을 넣고, 기존 원문을 보존해 선택 결과도 동일 엔진의 충돌 검사를 받는다. `destinationPickerPreservesConflictingNoticeAndCannotBypassReview`가 실제 UI에서 원문 동일성, 모든 확인 후 확정 비활성, 복사 미노출을 검증했다. [원문 보존 캡처](android-aosp28-rc1-picker.png)도 직접 확인했다. **이 발견 항목은 해결 확인으로 마감한다.**

**켜진 화면에서 만료 경계를 지나는 증거.** 최초 검토 시 정책 단위시험과 타이머 소스는 있었지만, 활성 화면의 실제 만료 경계 시험이 없었다. 이를 구현 실패로 단정하지 않고 실행 증거의 빈칸으로 전달했다. 추가된 `activeMemoAndQrExpireAtTheStoredDeadline`은 저장 시각을 만료 60초 전으로 준비하고 실제 경과 시간을 지나 QR drawable·메모 입력·저장소가 비워지며 가져가기가 비활성화되는지 검증했다. [만료 전](android-aosp28-rc1-ttl-before.png)·[만료 후](android-aosp28-rc1-ttl-after.png) 증거와 통과 로그를 확인했다.

이 두 항목의 해결을 임의 자연어 전체의 안전성 검증, 모든 화면의 접근성 승인 또는 이후 후보의 승인으로 확장하지 않는다.
