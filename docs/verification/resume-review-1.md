# 재개 후 독립 검토 1차

검토일: 2026-11-02 KST. 대상은 중단된 작업 폴더의 `1.0.0-rc1` 미커밋 소스다. 공식 심사나 이용자 조사 결과가 아닌 독립 에이전트 검토이며, 기존 심사 보고서와 점수는 이 판단의 근거로 읽지 않았다. 평가 중인 소스와 공개 저장소의 0.5 배포본은 서로 다르다.

## P1 행사 미개최의 일상적인 표현이 보류되지 않음

재현 위치: `dist/arrival/engine.mjs`의 `NOTICE_CHANGE`, `EVENT_STATUS_REFERENCE`, `extractDestinations`; 대응 Android 위치는 `BriefEngine.kt`의 `noticeChange`, `eventStatusReference`.

각 안내에 높이 `1.65`, 기본 `parked`를 넣어 `buildBrief({text, height:'1.65'})`를 호출하면 아래 네 사례 모두 `status:'ready', canConfirm:true`를 반환한다. 목적지 ID를 `auditorium`으로 직접 선택해도 같은 결함을 회귀 검증해야 한다.

| 입력 | 현재 결과 | 필요한 결과 |
| --- | --- | --- |
| `코엑스 오디토리움 3층\n오늘 행사는 안 합니다.` | ready / true | 원문 유지, 행사 상태 확인 필요, 확정 불가 |
| `코엑스 오디토리움 3층\n이번 행사는 하지 않습니다.` | ready / true | 원문 유지, 행사 상태 확인 필요, 확정 불가 |
| `COEX auditorium 3F. This event is not happening.` | ready / true | 원문 유지, 행사 상태 확인 필요, 확정 불가 |
| `COEX auditorium 3F. There is no event today.` | ready / true | 원문 유지, 행사 상태 확인 필요, 확정 불가 |

원인은 알려진 부정 문법이 열리다·진행·개최와 일부 상태 단어 중심이고, 일반적인 하다·happen·no event 표현을 놓치는 것이다. 단순한 장소명 후보 검출 자체는 문제가 아니지만, 명시적인 미개최 문장을 포함한 원문으로 공식 추천을 확정할 수 있다는 점이 문제다.

권고: 웹과 Android의 공통 계약으로 행사 상태 진술을 보류하고, 위 사례와 정상 소개·일시·입장권 안내를 함께 회귀 검증한다. 임의 자유문장의 완전한 의미 이해를 주장하지 않는다. 장소 선택이나 확인 체크를 추가해도 보류 원문이 우회되지 않는지 UI까지 확인한다.

## P1 최종 소스와 배포 증거를 하나의 버전으로 닫아야 함

검토 시점 `apk/ArrivalBrief_release.apk`와 `release-verification.json`은 `a10b1f7e...` 후보를 가리킨다. JSON은 웹 36개·공통 153사례를 기록하지만, 실제 현재 소스는 웹 47개 시험이 통과하고 공통 TSV는 229사례다. JSON의 `latest_version_status`도 후속 파서 수정을 기다리는 후보라고 명시한다. README가 안내하는 `android-runtime.md`는 0.4 실행 기록까지만 서술되어 있다.

이 상태로 포장하면 어느 수정까지 설치·실행한 것인지 독자가 판단할 수 없다. 최종 빌드의 입력 해시·APK 해시·설치된 APK 해시·UI 시험 대상 debug/test 해시를 대조하고, 현재 APK와 구 후보의 캡처·영상·문서를 분리해야 한다. 실패·중단된 시도는 성공 결과에 합치지 않는다. 최종 제출 ZIP의 소스 해시와 APK 복사본도 대조해야 한다.

## P2 QR 결과를 사용자가 바로 볼 수 있게 안내

`MainActivity.showMemoQr()`는 QR 패널을 보이게 하고 키보드를 닫지만, 새 결과에 초점을 주거나 화면 안으로 가져오지 않는다. UI 시험도 QR 버튼 클릭 뒤 QR 뷰에 별도로 `scrollTo()`를 호출한다. 현재 캡처에서 메모 입력·저장·삭제·가져가기·안내문 다음에 QR이 배치돼 있어, 낮은 화면이나 큰 글자에서는 결과가 화면 아래에서 생성될 수 있다.

권고: 허용 상태에서 QR 생성이 성공하면 레이아웃 완료 후 QR 제목·코드가 보이도록 이동하고 접근성 알림 또는 초점을 제공한다. 생성 성공 이후 사용자 추가 스크롤 없이 QR이 보이는지 일반 크기와 1.3배 글자에서 확인한다. 주행·미확인·화면 이탈·만료 시 지우는 동작은 유지한다.
