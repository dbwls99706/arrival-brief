## 개선 항목

### P2 원문 보류 이유를 사용자가 바로 찾기 어려움

엔진은 `eventNotes`, `facilityNotes`, `entryNotes`, `unparsedParkingNotes`에 문제가 된 문장을 보존한다. 웹의 `updateOptions()`와 결과 화면, Android의 결과 렌더링은 이 문장들을 별도로 보여주지 않고 행사 상태·시설 운영·주차·출입을 묶은 일반 설명을 표시한다. 원문 전체는 남아 있지만 긴 안내문에서 정확히 어느 문장이 검토 대상인지 스스로 찾아야 한다.

예시 입력:

```text
코엑스 오디토리움 3층
오늘 행사는 안 합니다.
```

기대 개선: `확인이 필요한 원문` 아래에 문제가 된 문장을 그대로 인용한다. 자동 수정이나 삭제를 제공하지 않는다. 한두 개만 요약해서 보여줄 때는 더 있는지 알리고 전체 원문 접근을 유지한다. 이 개선은 안전한 보류 판단의 근거를 사용자와 심사위원이 즉시 이해하게 한다.

### P2 Android 재확인 안내와 복사·보관 조건이 다름

소스에서 확인한 순서:

1. 현재 행사장·높이·주차를 확인해 브리핑을 확정한다.
2. 주행 또는 백그라운드 전환으로 `BriefSession.lock()`이 주차 확인과 현재 행사장 확인을 해제한다.
3. 입력이 허용된 뒤 주차 확인만 다시 체크한다.
4. `remainingConfirmation()`은 현재 유효한 행사장 확인을 요구하지만 복사·목적지 보관은 `editable && parkedConfirmed` 조건으로 활성화된다.

재확인 후 내보내기를 의도한다면 두 버튼의 활성 조건과 클릭 핸들러를 동일한 확인 조건에 연결해야 한다. 마지막 확정본의 재복사를 의도한 정책이라면 화면에 그 차이를 설명해야 한다. 이 항목은 코드 경로를 검토한 결과이며 이번 검토자가 실제 Android UI에서 다시 실행한 결과는 아니다.

## 직접 수행한 검사

- `node --test tests/*.test.mjs`: 48개 통과, 실패 0개.
- `python3 scripts/check-paths.py`: 로컬 참조 79개 통과.
- 독립 입력 검사: 한국어 행사 부정, 영어 행사 부정, 공식 추천과 다른 주차, 휴관 문구 각각에 자동·수동 선택을 적용해 확정이 차단됨을 확인했다.
- 정상 B3 블루존 안내는 세 확인을 모두 갖추면 통과하고, 행사장·높이·주차 확인 중 하나라도 해제하면 확정되지 않음을 확인했다.
- 주차 메모가 정확한 24시간 경계에서 만료되고 미래 저장 시각은 거부되며, 주행·미확인 상태에서는 메모 사용이 허용되지 않음을 확인했다.
- 위 독립 검사는 16개 assertion이며 사용자 수·실차 시험 횟수가 아니다.
