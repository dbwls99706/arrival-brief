## P1 종료된 행사 안내를 확정할 수 있음

현재 웹 엔진 `buildBrief`에서 다음 입력이 모두 `status: ready`, `canConfirm: true`가 된다.

```text
코엑스 오디토리움 3층
행사가 종료되었습니다.

코엑스 오디토리움 3층
이번 행사는 이미 끝났습니다.

COEX auditorium 3F. The event has ended.
```

각 입력에 `height: 1.65`를 넣고 `destinationId`를 비우거나 `auditorium`으로 지정한 두 경로에서 동일하게 재현했다. `오늘 행사는 안 합니다.`는 이미 `needs_review`로 보류된다.

장소가 알려져 있다는 이유로 행사 종료 상태를 무시하면 사용자가 과거 공지로 출발 준비를 확정할 수 있다. 행사 상태를 해석하는 범위에 완료·종료 범주를 포함하고, 상태문은 원문을 보존한 채 확인 필요로 처리할 것을 권고한다. `18시에 종료 예정`과 같은 시각 표현을 취소나 현재 종료로 단정해서는 안 된다. 자동·수동 선택 양쪽에 한국어·영어 회귀가 필요하다.

이는 모든 자유문장의 의미를 이해해야 한다는 요구가 아니다. 현재 명시적으로 검사하는 행사 상태 범위에서 흔히 사용하는 종료 상태가 누락된 문제다.

## P2 신규 원문 인용을 TalkBack이 읽지 못함

Android `MainActivity.kt`의 원문 인용 TextView는 실제 인용문을 `text`에 넣지만, `contentDescription`을 `확인이 필요한 원문 1` 같은 번호 설명으로 덮어쓴다. 접근성 서비스는 원문 대신 번호만 안내할 수 있다.

`contentDescription`에 실제 `excerpt`도 포함하거나, 별도 설정을 제거하여 TextView 본문을 읽게 해야 한다. 긴 원문의 `인용 일부` 표시는 유지한다.

## 확인한 개선

- `BriefSession.canExport()`가 기존 확정본과 현재 전체 확인 조건을 함께 요구한다. 복사·최근 목적지 저장의 버튼 활성 및 클릭 실행 모두 같은 조건을 사용한다.
- `showMemoQr()`는 QR 표시 후 허용 상태와 동일 비트맵을 재확인하고 QR 패널 시작으로 이동한다. 화면 이동 및 실제 완전 노출 결과는 진행 중인 최신 UI 시험으로 판정해야 한다.
- 웹의 보류 원문은 HTML escape 후 인용되고, 원래 입력값을 수정하거나 지우지 않는다. 최대 3개 문장과 생략 여부를 표시한다.
- 메모가 저장 후 24시간 경계에서 만료되고, 미래 시각·추가 필드가 있는 비정상 기록은 거부된다.
- 차량 상태가 주행·미확인일 때 확정이 금지되며, 행사장·높이·주차 확인 중 하나라도 빠지면 확정하지 못한다.
- 신청서 초안은 실제 주차 위치와 공식 추천을 구분하고, 같은 기기 공유와 차량 간 전송을 혼동하지 않는다. 실물 QR 스캔과 Pleos의 미검증 범위를 명시한다.
