# 다음 행사·새 시설 확대 승인표

이 문서는 제안된 내부 운영 기준이며 실제 승인·계약·시험 결과가 아니다. 소규모 기능 시험 통과만으로 대상 시설·차종을 늘리지 않는다.

## 현재 지원 범위의 다음 행사

| 승인 조건 | 제출할 증거 | 결정 |
| --- | --- | --- |
| 원문의 현재 행사장·층·운영 제약을 확인 | 채운 검토표와 버전이 있는 원문 | 불명확하면 보류 |
| 같은 전달 경로를 다시 사용할 수 있음 | 게시 권한, 실제 접근·설치·가져오기 재현, 수정 공지 담당 | 웹만 확인됐으면 웹 검증으로 한정 |
| 정상·보류 입력의 정책이 유지됨 | 5개 안내·3개 보류 합성 검증 및 실제 문안의 예상 결과 대조 | 잘못된 확정·제약 누락이 하나라도 있으면 해결 전 보류 |
| 반복 검토 비용을 감당할 수 있음 | 작성·검토·수정 시간, 미해결 상충·재검토 대기 목록 | 담당·처리 기한을 정하지 못하면 행사 수 확대 보류 |
| 다음 실험의 질문이 정해짐 | 과업, 분모, 관찰 기간, 사전 성공·중단 기준 | 행사 수 증가 자체를 성과로 삼지 않음 |

## 새 시설 또는 보류 분류의 안내 전환

1. 시설의 공식 출처와 현재 운영 범위를 확보하고, 검토·갱신 담당 및 정기 확인·변경 통지 방법을 정한다.
2. 명칭·시설 귀속·층·진입문·추천 주차·차량 제한과 서로 다른 원문을 대조한다. 충돌을 임의로 선택하거나 운영자의 주관으로 해제하지 않는다.
3. 기존 5개 안내·3개 보류를 그대로 유지한 상태에서 새 데이터 후보를 별도로 검토한다. 이 문서와 운영자 템플릿은 앱 지원 목록을 변경하지 않는다.
4. 정상 안내뿐 아니라 다른 시설·동명 장소·잘못된 층·취소·복수 장소·출입 제한·새 문법을 포함해 웹과 Android의 판정 일치를 검사한다.
5. 지원 차량 환경의 API·입력 제한·복귀를 재검증하고, 기기별 설치·안내문 도달 경로를 확인한다. 일반 Android 결과만으로 승인하지 않는다.
6. 승인한 데이터 버전, 검토 담당, 변경 이유와 되돌릴 이전 버전을 기록한 뒤 제한된 범위에서 평가한다. 오안내가 발견되면 해당 분류의 안내를 보류하고 영향받은 문안을 수정한다.

승인자는 자료·기술·배포·운영 책임을 각각 적는다. 한 명이 겸임할 수 있지만 각 항목의 근거는 생략하지 않는다. 확인일이 최근이라는 이유만으로 원문의 정확성을 보증하지 않는다.

## 유료 운영 기능을 검토할 조건

반복 행사에서 실제 담당자가 문안 작성·검토·수정을 수행할 수 있고, 문의·작업 시간이 어떻게 달라지는지 비교한 뒤 구매 주체와 반복 사용 의사를 확인한다. 유료 후보는 행사 안내 템플릿 관리, 출처 검토 이력, 수정 버전 배포 기록이다. 현재 앱에 운영자 서버·발송 서비스·유료 결제를 구현했다는 뜻이 아니다.

예산과 가격을 임의로 정해 매출로 환산하지 않는다. 표본·비교 조건·지원 비용을 기록한 후 가격과 기능 범위를 별도 실험한다. 이용자 수를 늘리기 위해 확정 조건을 느슨하게 하거나 보류 장소를 안내로 전환하지 않는다.
