# 이용자·운영자 과업 검증 기록표

**미작성 양식이다. 실제 실험·참가자 수·효과를 보고하지 않는다.** 아래 합성 과업으로 먼저 절차를 점검하고, 실제 참여는 동의와 환경 확인 후 진행한다. [사업성 검증 설계](../../docs/BUSINESS_VALIDATION.md)의 G1~G4와 지표 정의를 따른다.

## 1. 시작 전 작성

| 항목 | 기록 |
| --- | --- |
| 세션 ID / 관찰 날짜 / 관찰자 역할 | |
| 무작위 참여 ID / 역할(운전자·운영자) / 앱 사전 경험 | |
| 앱·데이터 버전 / 기기·OS / 조건 A·B 순서 | |
| 목적 / 과업별 제한 시간 / 사전 성공·중단 기준 | |
| 참여 동의 확인 / 기록 보관 기한 / 삭제 담당 | |
| 실제 차량이 안전하게 정차했는지 / 입력 허용 여부 | |

이름·연락처·계정·차량 번호·개인 행사 원문·실제 주차 메모는 기록하지 않는다. 연구 ID를 연락처와 연결하지 않으며, 화면 녹화·스크린샷은 기본 수집하지 않는다. 메모 과업에는 지정한 가상 문자열을 쓴다. 참여자는 중단할 수 있고, 관찰자는 정답이나 체크 위치를 먼저 알려주지 않는다. 차량 안에서는 **안전한 장소에 완전히 정차한 상태에서만** 실행한다. 주행하며 시험하지 않는다.

## 2. 가능한 환경을 먼저 고른다

| 구분 | 실행할 범위 | 이 결과로 주장할 수 없는 것 |
| --- | --- | --- |
| 일반 Android 탐색 | 차량 밖 또는 안전 정차 상태에서 데모 모드를 명시하고 아래 U1~U5·O1~O2 실행. 가상 차량 높이 1.65m를 제공 | 실제 차량 높이 확인, Pleos API·차량 입력 제한·설치 호환성 성공 |
| Pleos·지원 차량 검증 | G1의 지원 기기 설치·동일 기기 원문 전달·NaviHelper 응답·입력 제한과 복귀 근거 확인 후 해당 기기에서 실행 | 일반 Android 결과를 가져와 차량 결과로 대신 보고할 수 없음 |
| 실제 폰 QR 과업 | U4 이후 실물 폰 카메라로 U5만 별도 관찰 가능. 데모 화면이면 그 사실 기록 | 픽셀 디코드·에뮬레이터 캡처 성공으로 대체하거나 전체 차량·카메라 호환성으로 확대할 수 없음 |

Pleos 조건이 미확인되면 일반 Android 탐색까지만 진행한다. 앱의 데모·수동 체크로 차량 플랫폼 제한을 우회하지 않는다. 실제 차량 과업에서는 제공된 가상 높이를 쓰지 않고 적재물을 포함한 실제 전체 높이와 안전 상태를 직접 확인한다.

## 3. 비교 조건과 진행 순서

조건 A는 **같은 행사 안내 원문과 기존 코엑스 공식 안내 2종**, 조건 B는 **같은 원문과 Arrival Brief의 출처 표시**를 제공한다. 공식 안내 URL은 [운영 자료 README](README.md)에 있다. 사용한 원문·공식 자료 버전, 화면 크기·네트워크·허용된 도움과 제한 시간을 맞춘다. 최신 원문이 달라졌으면 예상 답을 다시 검토한다.

참여 ID에 따라 A→B와 B→A를 교대로 배정하고 순서를 기록한다. 동등한 난도의 서로 다른 합성 행사 사례를 쓰며 사례 배정도 기록한다. 같은 정답을 두 번 보거나 앱을 먼저 연습한 학습 효과를 구분한다. 적은 수의 탐색 결과를 인과적 시간 절감·문의 감소로 일반화하지 않는다. 공식 안내에 주차 메모·QR 기능이 없으면 해당 과업의 A는 ‘비교 해당 없음’으로 두고 실패로 세지 않는다.

관찰자는 원문을 제시할 때 시간을 시작하고, 참여자가 판단·설명을 마쳤거나 제한 시간에 도달하면 멈춘다. 도움이 필요하면 요청 시점·도움 내용을 적고 ‘도움 있음’으로 분리한다. 정답을 알려준 뒤의 완료를 무도움 성공으로 바꾸지 않는다.

## 4. 이용자 과업 — 예상 판정과 관찰 결과를 구분

모든 사례는 가상 과업이다. 원문을 임의로 줄여 보류를 통과시키지 않는다. 아래 기대는 관찰자의 채점 기준이며 참가자에게 먼저 읽어주지 않는다.

| ID | 참가자에게 주는 과업 | 관찰자의 예상 판정 |
| --- | --- | --- |
| U1 정상·등록층 구분 | `장소: 코엑스 아셈볼룸 2층`과 다음 줄 `참가 등록은 1층 로비에서 진행합니다.`를 가져와 행사장·등록층을 설명하고 준비한다 | 행사장은 2층, 등록은 1층으로 구분. 가상 높이·행사장·안전 확인 후 북문/B3 블루존 안내 후보. 등록층을 행사장으로 바꾸지 않음 |
| U2 장소별 차이 | [오디토리움 예시](01-auditorium.txt)와 [스튜디오159 예시](04-studio159.txt)를 서로 다른 과업으로 확인한다 | 각각 3층·북문/B3 블루존과 2층·동문/B2 퍼플존을 구분. 첫 장소의 결과를 다음 장소에 그대로 적용하지 않음 |
| U3a 출처 상충 | [301호 예시](07-rooms300.txt)를 확인하고 다음 행동을 설명한다 | 출처 상충 보류가 정답. 공식 원문을 확인하며 다른 회의실 선택으로 확정하지 않음 |
| U3b 취소 | `장소: 코엑스 아셈볼룸 2층`과 다음 줄 `이번 행사는 취소되었습니다.`를 확인한다 | 확정 보류가 정답. 취소 문장을 삭제해 확정하지 않고 최신 주최 안내 확인 필요를 설명 |
| U4 메모·재열람 | 안전 확인 후 가상 메모 `B3 블루존 G27 기둥 앞`을 저장하고 화면을 나갔다가 다시 확인한다 | 추천 주차와 실제 기록의 차이를 이해하고 가상 메모를 다시 읽음. 종료 시 기록 삭제. 이번 연습의 재열람은 실제 같은 방문 재사용 성과가 아님 |
| U5 실물 폰 QR | U4의 저장값을 QR로 표시해 실물 폰에서 읽고 임시로 저장·재열람한다 | 원문과 일치하는 가상 메모를 별도 저장. 폰 복사본에는 앱 만료·삭제가 적용되지 않음을 설명하고 시험 후 양쪽 기록 삭제 |

U5는 카메라 앱·기기/OS, 화면 밝기, 대략적 읽기 거리, 첫 시도와 조정 후 결과를 따로 적는다. QR 표시만으로 성공 처리하지 않는다. 폰에서 읽거나 저장하지 못하면 실패 또는 미완료이며, 재시도 성공도 첫 시도 실패를 지우지 않는다.

## 5. 운영자 과업 — 실제 발송하지 않는 리허설

| ID | 과업 | 관찰할 결과 |
| --- | --- | --- |
| O1 작성·검토 | U1 가상 행사를 [안내문 템플릿](participant-notice-template.md)에 작성하고 [검토표](review-checklist.md)를 채운다 | 정확한 장소/등록층·출처·버전·제약 보존, 미확인 항목 보류. 작성·출처 검토·수정 시간을 각각 기록 |
| O2 변경·재배포 준비 | 관찰자가 ‘같은 가상 행사가 취소됨’이라는 새 원문을 제공한다. 이전 버전 표시와 수정 문안을 준비한다 | 취소를 숨기지 않고 최신 버전·기존 안내 회수 위치·동일 채널 재전달 담당을 기록. 실제 연락·게시·발송은 하지 않음 |

## 6. 빈 관찰 기록 — 과업마다 한 줄씩 복제

| 참여 ID / 과업·사례 / A·B | 성공·실패·미완료·중단·미실행 | 도움 없음·있음 / 내용 | 시간(초) | 오확정·보류 판단 / 이유 | 재시도·관찰 메모 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |
| | | | | | |
| | | | | | |

U5 환경·첫 시도·조정 후 결과: `________________________________________________`

O1/O2 작성 / 출처 검토 / 수정 / 재배포 준비 시간(각 분): `____________________________`

잘못된 장소·시설·높이 초과 확정 또는 주행 입력 유도 1건이라도 발견하면 해당 흐름을 멈추고 원인·조치·재시험 전 확대 보류를 기록한다. 원문 누락이나 도움을 숨기지 않는다. 보류가 정답인 과업의 올바른 보류는 성공으로, 강제 확정은 실패로 분류한다.

## 7. 빈 집계와 다음 결정

| 집계 | 분자 / 분모·기록 |
| --- | --- |
| 장소 확인 무도움 완료 | 지원 안내를 받은 과업 참여자 중 장소 확인에 도달한 고유 사람 / 대상 고유 사람: ____ / ____ |
| 정상 과업 / 보류 과업 | 각각 무도움 성공·도움 후 완료·실패·미실행 수와 과업 수: __________________ |
| 잘못된 확정 | 건수 / 전체 관찰 과업: ____ / ____ (사건 ID: ____) |
| 폰 가져가기 | 실제 폰에서 읽고 별도 저장한 사람 / U5 시도자: ____ / ____ (첫 시도·재시도 구분) |
| 시간 비교 | A·B별 과업 시간, 도움·순서·사례 차이, 시간 초과 포함: __________________ |
| 다음 결정 | 유지 / 수정 후 재시험 / 확대 보류, 이유·담당·기한: __________________ |

같은 사람의 여러 과업을 입력 완료율 분모에 여러 명으로 더하지 않는다. 순이용자를 확인할 수 없으면 세션·과업 수만 보고한다. 이 탐색 표의 반복 실행·메모 재열람·QR 복사본 확인은 **MAU, 30일 재사용률, 방문 기회 기준 재사용률로 계산하지 않는다.** 실제 방문의 후속 검증은 별도 동의·관찰 기간·기회 확인이 필요하며, 정의와 분모는 사업성 문서를 따른다. 작은 탐색에서 오류가 없었다는 사실도 안전성 보증이나 효과 입증은 아니다.
