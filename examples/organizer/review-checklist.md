# 행사 안내 검토·배포 기록표

상태는 `확인 / 보류 / 해당 없음`으로 작성하고, ‘확인’에는 근거와 검토자를 남긴다. 빈칸은 확인 완료가 아니다. 이 파일은 미작성 양식이며 완료 증거가 아니다.

| 기본 기록 | 작성란 |
| --- | --- |
| 행사 ID / 안내 버전 | |
| 행사 일시 / 시설·행사장·층 | |
| 원문 파일 또는 URL / 원문 확인 시각 | |
| 앱 버전 / 데이터 버전 | |
| 작성 담당 / 검토 담당 / 승인 시각 | |
| 배포 채널·권한 / 최신 안내 URL | |
| 변경 공지 담당 / 이전 버전 회수·표시 위치 | |

| 점검 항목 | 상태 | 근거·결과·담당 |
| --- | --- | --- |
| 실제 행사와 현재 장소·층을 주최 측 원문으로 확인했다 | | |
| 현재 안내 5개/보류 3개 중 분류를 확인했고 미지원 장소를 대체하지 않았다 | | |
| 행사장 층·등록층·주차층을 구분하고 복수 장소와 일정을 숨기지 않았다 | | |
| 공식 시설 자료의 URL·확인일·상충 여부를 기록했다 | | |
| 출입·주차 제한, 취소·변경·운영 상태 문장을 원문대로 보존했다 | | |
| 현장 표지와 최신 운영 안내 우선, 빈자리·진입 가능 실시간 보장 없음이 전달된다 | | |
| 사람마다 다른 차량 전체 높이와 안전 주차를 운영자가 대신 체크하지 않는다 | | |
| 웹 주소가 실제 열리며 원문 파일은 UTF-8 `.txt`, 40KB 이하·10,000자 이내다 | | |
| 차량용이라고 안내할 경우 지원 기기의 설치·같은 기기 원문 도달·차량 제한을 재현했다 | | |
| 동일 기기 공유를 휴대폰→차량 자동 전송으로 소개하지 않는다 | | |
| 문안 그대로 가져온 결과를 확인했고 보류를 통과시키려고 원문을 편집하지 않았다 | | |
| 잘못된 시설·층·높이, 운영 제한, 출처 상충은 확정 보류됨을 확인했다 | | |
| 메모·QR를 소개하면 실제 위치 수동 기록, 복사본 수명 차이와 카메라 검증 범위를 설명한다 | | |
| 배포 권한·수신 범위·수정 재전달 채널과 실패 시 대응 담당을 정했다 | | |
| 참가자의 원문·주차 위치·연락처를 시험 보고서나 공개 저장소에 넣지 않는다 | | |

## 승인과 보류

최종 판정: `[게시 가능 / 공식 원문만 제공·앱 확정 안내 보류 / 전체 게시 보류]`

판정 이유: `[미해결 항목과 조치 담당·기한]`

앱의 ‘안내 후보’는 운영자의 행사 확인이나 배포 승인을 대신하지 않는다. 특히 3개 출처 상충 분류는 현장 답변을 받았다는 메모만으로 앱의 보류가 풀리지 않는다. 공식 근거와 데이터 변경 검토·양쪽 엔진 검증을 거쳐야 한다. 원문이 변경되면 이전 승인 상태를 그대로 재사용하지 않는다.

| 최초 게시·수정 게시 시각과 버전 | |

| 장소·층·주차 문의 | 유형별 건수와 중복 처리 규칙 / |
| 잘못된 확정·원문 누락·자료 상충 | 사건 ID·재현 입력(개인정보 제거)·조치 상태 / |
| 다음 행사에서 바꿀 점 | |

문의가 없었다는 이유만으로 도움이 되었다고 판단하지 않는다. 정확한 참가자 수·전달 여부를 모르면 분모를 만들지 않고 관측 가능한 건수만 보고한다.
