# Arrival Brief UI 개편 참고 자료

확인일: 2026-10-31

## 요청과 범위

사용자는 내장 디자인 스킬 대신 인터넷에 공개된 외부 스킬과 설계자의 고민이 드러나는 레퍼런스를 참고해 앱 전체를 다듬고, UI/UX 심사위원 에이전트의 검토를 받도록 요청했다. 이 문서는 자료 선정과 적용 판단을 기록한다. 사용자 인터뷰나 실제 차량 사용성 검증을 실시했다는 뜻은 아니다.

외부 문서는 읽기 전용으로 조사했다. Impeccable을 설치하거나 해당 CLI, detector, hook을 실행하지 않았다. 스킬 본문과 참고 사이트의 이미지·페이지 코드를 이 변경에 복제하지 않는다.

확인한 SKILL.md 버전은 4.8.0, 라이선스는 Apache 2.0이다. Arrival Brief의 작업 화면에는 Operate 분류를 참고한다. 사용자가 수행할 일, 읽기 쉬운 정보 구조, 익숙한 조작, 일관된 상태 표현을 우선한다. 한 서체 계열과 절제된 크기 체계를 사용하고 강조색은 주요 행동·현재 선택·상태에 집중한다. 장식용 모션과 페이지 진입 연출은 추가하지 않는다. 실제 화면 크기에서 렌더링을 확인한다는 원칙도 채택한다.

공개 반응은 호평 일색이 아니다. 아래 Hacker News 글은 확인 당시 103점과 64댓글이 있었지만, 개선 예시에서 유용한 정보가 사라지거나 가독성이 떨어졌다는 비판도 포함했다. 작성자 paulbakaus는 성급한 예시를 삭제하고 문구·타이포·스크롤 문제를 수정했다고 답했다. 관심도 수치를 품질 보증으로 취급하지 않으며, 기능과 필요한 정보를 보존하는지 별도로 검토한다.

- 토론 및 작성자 답변: https://news.ycombinator.com/item?id=46587284

### Anthony Hobday - 간격과 대비에 이유를 부여하기

- 저자 원문: https://anthonyhobday.com/sideprojects/saferules/

저자가 규칙의 이유와 비교 이미지를 직접 설명한 자료다. 중요한 내용은 강한 대비로, 구조를 위한 선과 배경은 낮은 대비로 구분한다. 관련 요소끼리 가까이 놓고 간격을 공통 척도로 정리한다. 글자·아이콘·컨트롤의 정렬과 시각적 무게를 함께 확인한다. 저자도 타당한 이유가 있으면 규칙을 벗어날 수 있다고 설명하므로 차량 화면의 제약에 우선 적용하지 않는다.

공개 열람 자료로 참고했으며 글과 이미지의 재배포 라이선스는 확인하지 않았다. 원문을 복제하지 않고 설계 원칙을 적용한다.

## 이번 개편의 시각 방향

- 작업 공간은 밝은 실버·아이보리 계열로 정돈한다. 전체 화면을 어둡게 바꾸지 않는다.
- 딥 네이비를 주요 행동과 선택에 제한적으로 사용한다. 현대자동차그룹 로고나 공식 서비스로 오인할 표시는 추가하지 않는다.
- 도착 브리핑은 어두운 그래파이트 패널로 구분해 결과에 시선을 모은다.
- 한글 서체 한 계열, 8/16/24/32 간격, 일관된 아이콘 획과 크기를 사용한다.
- 선택·주의·오류·확정의 의미 색상을 구분하고, 색상만으로 상태를 전달하지 않는다.
- 그라디언트 글자, 장식용 광채, 무의미한 애니메이션, 동일한 카드의 반복을 피한다.

이는 참고 자료를 Arrival Brief에 맞게 해석한 설계 결정이다. 외부 저자의 승인이나 현대자동차그룹의 공식 디자인 지침을 뜻하지 않는다.

## 기존 코드에서 확인한 개선 대상

`dist/arrival/index.html`과 `dist/arrival/style.css`를 읽었을 때의 관찰이다. 아래 항목은 개선 완료나 화면 심사 통과를 의미하지 않는다.

| 관찰 | 적용 방향 |
| --- | --- |
| 안내·모드 설정·입력·확인·최근 기록이 한꺼번에 경쟁 | 장소 선택과 현재 필요한 행동을 우선하고 단계별 상태를 명확하게 표시 |
| 설명 문장이 많아 입력과 결과의 연결이 약함 | 장소 확인, 차량 확인, 도착 브리핑의 관계를 같은 시각 언어로 연결 |
| 출처·지원 범위·개인정보 설명이 화면을 길게 만듦 | 일반 설명은 펼쳐볼 수 있게 정리하되 현재 판단에 필요한 출처 충돌과 높이 제한은 노출 |
| 비어 있는 최근 기록에도 여러 조작이 보임 | 비어 있을 때는 사용 방법을 짧게, 기록이 있을 때는 실제 장소와 가능한 행동을 표시 |
| 작은 보조 글자와 누적된 CSS override | 중요 정보의 가독성을 높이고 색상·간격·컨트롤 규칙을 통합 |

## 독립 심사와 확인 기준

별도 심사위원 에이전트가 변경 후 스크린샷과 실제 상태를 검토한다. 이 문서 작성 시점에 그 검토 결과나 완료 점수를 기록하지 않는다. 기능·접근성 확인과 시각 평가를 구분하고, 미실시 항목은 그대로 명시한다.

1. 첫 화면에서 현재 상태와 시작할 행동을 찾을 수 있는가.
2. 확정 결과의 입구·주차 위치·최종 목적지를 중요도 순서대로 읽을 수 있는가.
3. 정보 충돌·높이 미확인·미지원 장소를 성공 상태와 구분할 수 있는가.
4. 정차·주행·미확인 모드의 조작 제한과 화면 표현이 일치하는가.
5. 작은 화면, 차량 가로 화면, 확대 환경에서 필수 내용이 잘리거나 겹치지 않는가.
6. 키보드 초점, 입력 오류, 완료 알림과 주요 컨트롤을 식별할 수 있는가.
7. 필요한 정보와 동작을 보존하면서 장식과 중복 설명만 줄였는가.

실제 차량 적합성, 운전 중 안전성, 사용자 만족도는 스크린샷 검토만으로 입증할 수 없다.
